1 Introduction

This page contains additional Quarto material that builds on the w14a lecture. You’ll learn about chunk labels and two optional Positron features for Quarto documents, how to cite papers and software, how to avoid re-running slow code every time you render a document, and how to turn an existing R script into a Quarto document. Finally, you’ll see a few examples of using Claude to make slides, add references, and build a website with Quarto.

2 Chunk labels

You can give a chunk a label with #| label: <label-name>. Labels must be unique within a document and cannot contain spaces. They show up in messages during rendering, which makes it easier to find the chunk that caused a problem:

```{r}
#| label: my-first-chunk
2 + 3
```
[1] 5

3 Positron features for Quarto documents

3.1 Showing the output below each chunk

Positron can optionally show the output of each chunk right below it in the editor, as RStudio does by default. To turn this on, open the Settings and enable quarto.inlineOutput.enabled.

With this setting turned on, Positron runs the code of each Quarto document in a separate R session, whose Console is not shown by default (to show it, enable console.showNotebookConsoles). The working directory of that R session is the document’s folder, just like when you render. So, if your document is directly inside the folder you opened, your code works the same as in your regular Console.

3.2 The visual editor

So far, you’ve edited Quarto documents in the default source editor, where you type everything yourself: the text, the code chunks, and the YAML header. This gives you full control, but requires knowing some Markdown and Quarto syntax.

Positron also has a visual editor for Quarto documents, which is the same one you may have used for Markdown files in VS Code in week 7, since both use the Quarto extension. In the visual editor, you can format text and add elements like tables and images with toolbar buttons, and see roughly how your document will look as you write, much like in Word or Google Docs.

To switch between the two editors, click the ... button in the top-right of the editor, and select “Edit in Visual Mode” or “Edit in Source Mode”.

4 Citations and references

Quarto can add citations and a reference list to your document, which is useful in reports, thesis chapters, and papers. This works in three steps:

  1. Store your references in a bibliography file.
  2. Point to that file in the YAML header.
  3. Cite references by their key in the text.

4.1 The bibliography file

The most common bibliography format is BibTeX, whose files have the extension .bib. Each entry in a BibTeX file describes one reference, and starts with a citation key that you use to cite it — love2014 in this example:

references.bib
@article{love2014,
  title = {Moderated estimation of fold change and dispersion for {RNA}-seq data with {DESeq2}},
  author = {Love, Michael I. and Huber, Wolfgang and Anders, Simon},
  year = {2014},
  journal = {Genome Biology},
  volume = {15},
  pages = {550},
  doi = {10.1186/s13059-014-0550-8}
}

You rarely have to type these entries yourself:

  • Most journal websites have an “Export citation” or “Cite” button with a BibTeX option.
  • Reference managers like Zotero can export your library, or part of it, to a .bib file.
  • For R packages, run citation("<package-name>") in the R console, which prints the package’s preferred citation, including a BibTeX entry.
  • In Positron’s visual editor, you can use “Insert” > “Citation” to look up a reference by its DOI, or search for it, and Quarto will add its entry to your bibliography file.

4.2 Pointing to the bibliography file

Add the bibliography key to your YAML header, with the path to your .bib file (relative to the Quarto document, like other paths in the YAML header):

---
title: "My report"
bibliography: references.bib
---

4.3 Citing references

To cite a reference in your text, use @ followed by its citation key, usually inside square brackets:

Markdown Rendered output
DESeq2 [@love2014] is used... DESeq2 (Love et al. 2014) is used…
As shown by @love2014, ... As shown by Love et al. (2014), …
[@love2014; @markowetz2015] (Love et al. 2014; Markowetz 2015)
[see @love2014, p. 3] (see Love et al. 2014, 3)

When you render the document, Quarto formats each citation, and adds a reference list with all cited references at the end of the document — as you can see at the bottom of this page. To put the reference list elsewhere, for example before an appendix, add an empty refs div in that spot:

## References

::: {#refs}
:::

4.4 Citation styles

By default, Quarto uses the Chicago author-date style. To use a different style, such as that of the journal you are submitting to, download its .csl file from the Zotero Style Repository , and point to it with the csl key in the YAML header:

---
title: "My report"
bibliography: references.bib
csl: genome-biology.csl
---

5 Avoiding slow re-renders with caching

5.1 Why caching?

Every time you render a Quarto document, all of its code is run again, in a new R session (see how rendering works). That is what makes rendering reproducible, but it gets tedious when one chunk takes minutes to run — like running DESeq() for a differential expression analysis next week — while you’re only editing the text.

With caching, Quarto saves the results of a chunk the first time it runs, and loads those saved results in later renders instead of running the code again.

5.2 Turning on caching

You can turn on caching for a single chunk with the cache chunk option:

```{r}
#| cache: true
dds <- DESeq(dds)
```

Or for all chunks in the document, under execute: in the YAML header:

---
title: "My report"
execute:
  cache: true
---

The saved results go in a folder next to your document: for report.qmd, that is report_cache. Don’t commit this folder to Git — instead, add it to your .gitignore file, for example with the pattern *_cache/.

Caching only affects rendering: when you run a chunk interactively, it always runs.

5.3 When cached results get outdated

A cached chunk is run again only when its own code (or its chunk options) changes. Quarto does not check whether anything else that the chunk uses has changed, such as an object made in an earlier chunk, or an input file. In those cases, the rendered document will show outdated results.

For that reason:

  • Only cache the slow chunks, rather than turning on caching for the whole document.

  • When an earlier chunk or an input file has changed, re-run all cached chunks with the --cache-refresh option:

    quarto render report.qmd --cache-refresh

  • Before you share final results, render the document once with --cache-refresh, or with caching turned off.

NoteWhat about freeze? (Click to expand)

When you search for ways to speed up rendering, you’ll also come across the freeze option. This option only applies to Quarto projects: folders with a _quarto.yml file, such as websites (like this one!) and books. With freeze, documents in a project are only re-run when their source file changes, rather than every time the whole project is rendered.

freeze is not used when you render a single document, so for your own Quarto documents, use cache instead.

Exercise: Caching

  1. Create a new Quarto document with a chunk that takes 5 seconds to run, and prints the current time:

    Sys.sleep(5)
Sys.time()

    Render the document twice: does it take equally long both times?

      Click to see the solution

    Yes: without caching, the chunk is run in each render, so each render takes at least 5 seconds, and the printed time changes.

  2. Add #| cache: true to the chunk, and render the document twice again. What has changed, and what has been created in the Explorer?

      Click to see the solution

    The first render still takes 5 seconds, but the second one is quick, and shows the same time as the first one, because the saved results are used instead of running the code. A new folder with the same name as your document plus _cache has been created.

  3. Render the document from the terminal with the --cache-refresh option. Is the printed time updated?

    Yes: with --cache-refresh, the cached chunk is run again, so the render takes 5 seconds and the time is updated.

6 Turning an R script into a Quarto document

If you have R code in an R script (a .R file), you may want to turn it into a Quarto document, so you can add explanations and render a report with its results.

6.1 By hand

The most straightforward way is to do it by hand:

  1. Create a new Quarto document, and add a YAML header.
  2. Paste the code into code chunks, starting a new chunk at each logical step of your analysis, like loading the data or making a plot.
  3. Turn comments that explain the code into Markdown text between the chunks, and turn section comments into Markdown headers.
  4. Render the document to check that it works, keeping in mind that the working directory may differ from the one you ran the script in.

6.2 Using special comments

Alternatively, you can mark up the script itself with special comments:

  • Lines starting with #' (a #, a single quote, and a space) are Markdown text, including the YAML header.
  • Lines starting with #| are chunk options, just like in a Quarto document.
  • Lines starting with #+ start a new chunk. A new chunk is also started after each block of #' lines.

For example:

analysis.R
#' ---
#' title: "My analysis"
#' format:
#'   html:
#'     embed-resources: true
#' ---

#' ## Load the data
#| message: false
library(tidyverse)
meta <- read_tsv("metadata.tsv")

#' ## Count the samples
#' The number of samples per treatment:
meta |> count(treatment)

Because these lines start with #, the file is still a valid R script, which you can run as usual. But you can now also do one of two things with it:

  • Render the script directly to a report, with quarto render analysis.R.

  • Convert it to a Quarto document, by running the following in the R console, which creates the file analysis.qmd:

    knitr::spin("analysis.R", knit = FALSE, format = "qmd")

    You can then continue working in the Quarto document, though you may want to tidy it up a bit, for example to remove empty lines at the end of chunks.

6.3 Asking Claude

You can also ask Claude to do the conversion, for example:

Turn scripts/analysis.R into a Quarto document analysis.qmd. Split the code into chunks at each logical step, with a Markdown header for each step, and turn the comments that explain the code into Markdown text. Don’t change the code itself.

Claude’s conversion is usually more polished than one with knitr::spin(), but compare the code in the new document with the code in the script, to make sure that Claude didn’t change it along the way. Then, render the document, keeping in mind that the working directory may differ from the one you ran the script in.

7 Quarto with Claude

Quarto can do much more than the HTML reports we’ve made in this course, and Claude is a good guide to features you haven’t used before. Here are a few examples of what you can ask it.

7.1 Slides

Quarto can render a document as a slide deck, with format: revealjs in the YAML header. Each ## header then starts a new slide, and code chunks work just like in other Quarto documents. For example, to turn your week 15 report into slides:

Create a Quarto revealjs slide deck slides.qmd from reports/w15_exercises.qmd for a 10-minute lab meeting presentation. Put one plot per slide, hide all code, and keep the inline code for any numbers.

Then, check that:

  • The numbers in the slides still come from inline code, rather than being typed in, so that they stay correct when your analysis changes.
  • The slides render, and that the plots fit on the slides (you may need to adjust the figure sizes with fig-width and fig-height).

7.2 Adding references

Claude can add citations and a bibliography file to your document, but don’t let it write the BibTeX entries from memory, because it may get details like the DOI or page numbers wrong. Instead, ask it to get the entries from their DOIs, which it can do with a shell command, or with citation() for R packages:

Add a references.bib file and cite DESeq2 and the Garrigós et al. (2025) paper in the introduction of reports/w15_exercises.qmd. Get the BibTeX entry for the paper from its DOI, and for DESeq2 from citation(“DESeq2”), rather than writing them yourself.

Then, check that each entry in references.bib is for the reference you meant, for example by clicking its DOI link.

7.3 A website

This course’s website is a Quarto website: a set of Quarto documents in one folder, with a configuration file _quarto.yml that defines, for example, the navigation bar. You can make a personal or lab website the same way, and host it for free on GitHub Pages:

Create a Quarto website for my lab in a new folder lab-website, with pages for Home, People, Research, and Publications, and a navigation bar. Render it, and explain how to preview it and how to publish it on GitHub Pages.

To see your website while you work on it, run quarto preview in the terminal, inside the website’s folder. This renders the website, shows it in a browser, and updates it whenever you save a change to one of its pages.
