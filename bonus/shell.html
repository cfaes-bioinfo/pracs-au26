2 Other shell wildcards

In w4b, you learned about globbing (selecting files) with the * wildcard. While not as frequently used as *, a few other shell wildcards exist. Here is a complete overview of shell wildcards:

Wildcard Matches
* Any number of any characters, including none
? Exactly one of any character
[...] Exactly one of the characters listed in the brackets
[^...] Exactly one character that is not listed in the brackets

To get set up, create some dummy FASTQ files to practice with:

# (You should be in /fs/ess/PAS3493/people/$USER/week04/sandbox)
# (If you did the w4b globbing section, these files already exist)
touch sample1_R1.fastq sample1_R2.fastq
touch sample2_R1.fastq sample2_R2.fastq
touch sample3_R1.fastq sample3_R2.fastq

Using the more restrictive wildcard ? can be useful to prevent accidental matches. Here is an example of using the ? wildcard to match both R1 and R2:

ls sample1_R?.fastq
sample1_R1.fastq  sample1_R2.fastq

The character class wildcard [] can be useful when you want to include or exclude multiple files among a set of files with rather similar names. For example, to match files for sample1 and sample2 using only a character class with []:

  • Method 1 – List all possible characters (1 and 2 in this case):

    # This is saying: after 'sample', there should be a 1 OR a 2 ('[12]'),
# followed by any character (*):
ls sample[12]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 2 – Use a range like [0-9], [A-Z], [a-z]:

    ls sample[1-2]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

  • Method 3 – Exclude the unwanted sample ID by prefacing the character class with a ^, which results in inverted behaviour:

    # This is saying: after 'sample', there should be anything EXCEPT a '3':
ls sample[^3]*
    sample1_R1.fastq  sample1_R2.fastq  sample2_R1.fastq  sample2_R2.fastq

These examples may seem trivial, but you can use these techniques to easily operate on selections among 100s or 1000s of files.

WarningA character class always matches a single character

So [10-13] does not mean “10 through 13”: it is read as “one character that is 1, 0-1, or 3”. To match multi-digit numbers, use separate patterns (e.g. sample1[0-3]*) or brace expansion (next section).

3 Brace expansion

Brace expansion with {} is another type of shell expansion, but it works very differently from wildcards: a wildcard expands only to names of files that already exist, whereas brace expansion expands to whatever you tell it to, whether or not such files exist. That makes brace expansion the tool for creating many files or dirs with mkdir and touch, and wildcards the tool for selecting existing ones.

For example, use .. within {} to indicate ranges of numbers or letters:

  • Create 30 directories, one for each day in September:

    # Writing '01' keeps the leading zero, so that alphabetical order = date order:
mkdir -p 2026-09-{01..30}

ls 2026-09*
    2026-09-01  2026-09-04  2026-09-07  2026-09-10  2026-09-13  2026-09-16  2026-09-19  2026-09-22  2026-09-25  2026-09-28
2026-09-02  2026-09-05  2026-09-08  2026-09-11  2026-09-14  2026-09-17  2026-09-20  2026-09-23  2026-09-26  2026-09-29
2026-09-03  2026-09-06  2026-09-09  2026-09-12  2026-09-15  2026-09-18  2026-09-21  2026-09-24  2026-09-27  2026-09-30

  • Create 6 empty files:

    touch fig-1{A..F}.png

ls fig-*
    fig-1A.png  fig-1B.png  fig-1C.png  fig-1D.png  fig-1E.png  fig-1F.png

As the example below shows, you can also:

  • Use a comma-separated list, and
  • Combine multiple brace expansions to get all combinations among values in the expansions
mkdir -p treatment-{Kr,Df,Tr}_temp-{lo,med,hi}

ls treatment-*
treatment-Df_temp-hi   treatment-Kr_temp-hi   treatment-Tr_temp-hi
treatment-Df_temp-lo   treatment-Kr_temp-lo   treatment-Tr_temp-lo
treatment-Df_temp-med  treatment-Kr_temp-med  treatment-Tr_temp-med

4 Globbing across dirs

4.1 Wildcards in dir names

So far, you have used wildcards to match the names of files in a single dir, like *.fastq or data/*.fastq. But a wildcard can also stand in for a dir name, at any level of a path.

To try this, create a dummy results dir with a subdir for each of three samples, like the output of a program that writes a separate subdir for each sample:

# (You should be in /fs/ess/PAS3493/people/$USER/week04/sandbox)
mkdir -p results/S{1..3}/logs
touch results/S{1..3}/counts.tsv results/S{1..3}/logs/run.log results/README.md

Now, you can use a * in place of the sample dir name to select the files of all samples at once:

ls results/*/counts.tsv
results/S1/counts.tsv  results/S2/counts.tsv  results/S3/counts.tsv

You can also use wildcards at several levels of a path:

ls results/*/logs/*.log
results/S1/logs/run.log  results/S2/logs/run.log  results/S3/logs/run.log

A pattern that ends in a / only matches dirs. To see this, use echo, which simply prints what the pattern expands to (with ls, you’d instead see the contents of the matched dirs). First, a pattern without a trailing /, which matches the README.md file too:

echo results/*
results/README.md results/S1 results/S2 results/S3

With a trailing /, only the dirs are matched:

echo results/*/
results/S1/ results/S2/ results/S3/

4.2 Recursive globbing with **

A * never matches across levels of a path: the * in results/*.log only matches names of files and dirs directly in results, so this pattern doesn’t match the log files in the sample dirs.

When the files you want are at different or unknown depths, you can use **, which matches any number of dir levels, including none. This only works after you turn on the globstar option with the shopt (“shell options”) command:

# 'shopt -s' sets (turns on) an option:
shopt -s globstar

ls results/**/*.log
results/S1/logs/run.log  results/S2/logs/run.log  results/S3/logs/run.log

The command find results -name "*.log" would give the same result. Globbing with ** is shorter and works directly with any command, whereas the find command (see below) is more flexible: for example, it can also select files by type, size, or date.

WarningWithout globstar, ** acts like a single *

If the globstar option is off, you won’t get an error message: results/**/*.log will silently be treated like results/*/*.log, which only matches files exactly one level down.

4.3 When nothing matches: nullglob and failglob

Recall from w7b that when a glob doesn’t match any files, the shell leaves the pattern as is, so a loop will run once with the pattern itself as the “file name”:

for file in results/*.bam; do
    echo "Found file $file"
done
Found file results/*.bam

If you turn on the nullglob option, a glob that doesn’t match anything instead expands to nothing, so the loop doesn’t run at all:

shopt -s nullglob

for file in results/*.bam; do
    echo "Found file $file"
done
# (No output)

But nullglob can also change what other commands do. For example, when its only argument is an unmatched glob, ls now receives no arguments at all, and therefore lists the contents of your working dir:

ls results/*.bam
# [Output: all files and dirs in your working dir]

Shell options stay in effect for the rest of your shell session, so turn nullglob off again with shopt -u (for “unset”):

shopt -u nullglob

# Check whether an option is on or off:
shopt nullglob
nullglob        off

The related failglob option makes an unmatched glob an error: the shell prints a no match error and doesn’t run the command. In a script, this also makes the script stop.

Both options are mostly useful in shell scripts. Because a script runs in a new shell, options that you set in a script only apply to that script, and you would set them right below the set -euo pipefail line. Which option to use depends on what should happen if no files match:

  • failglob when no matching files means that something went wrong, e.g. when looping over input files that should exist. Then, the script stops instead of running a command on a non-existent “file”.
  • nullglob when no matching files is a valid situation, e.g. when looping over optional files that may or may not be present.
NoteHidden files (Click to expand)

By default, wildcards don’t match hidden files, i.e. files whose names start with a ., like .gitignore. To make them match hidden files too, turn on the dotglob option with shopt -s dotglob.

5 The find command to find files

5.1 Two problems you may run into

Consider the following two problems you may run into, adapted from Buffalo (2015). Say that you try to pipe ls output into the imaginary program process_fastq, which can operate on multiple FASTQ files at once, taking each as an argument:

ls *.fastq | process_fastq

Any spaces in the listed file names would lead to trouble here, since those file names would be erroneously split into separate arguments. A solution would be to use direct globbing:

process_fastq *.fastq

However, a different problem could occur here: if the number of globbed files is very high, you may get an error that the “argument list is too long”.

The find and xargs commands can deal with both of these problems. More generally, they are useful for:

  • find: file searching and processing beyond ls’s capabilities.
  • xargs: multi-file and parallel processing without loops.

Let’s create a small dummy project to try these commands, modeled on the maize SNP project from Buffalo (2015):

mkdir -p zmays-snps/{data/seqs,scripts,analysis}
touch zmays-snps/data/seqs/zmays{A,B,C}_R{1,2}.fastq

5.2 find basics

The basic syntax for find is:

find [path] [expression-1] [expression-2] ...

find will print all files by default, like ls — but unlike ls, it is recursive by default:

find zmays-snps
zmays-snps
zmays-snps/data
zmays-snps/data/seqs
zmays-snps/data/seqs/zmaysC_R1.fastq
zmays-snps/data/seqs/zmaysA_R1.fastq
zmays-snps/data/seqs/zmaysB_R1.fastq
zmays-snps/data/seqs/zmaysB_R2.fastq
zmays-snps/data/seqs/zmaysC_R2.fastq
zmays-snps/data/seqs/zmaysA_R2.fastq
zmays-snps/scripts
zmays-snps/analysis

Compare this with the corresponding ls output:

ls zmays-snps
analysis  data  scripts

Using the -name option, you can also glob like with ls:

cd zmays-snps
find data/seqs -name "zmaysB*fastq"
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

5.3 find functionality beyond that of ls

First, you can use -type as an expression to limit results by file type:

# "-type f" to only match regular files (not, e.g., dirs)
find data/seqs -name "zmaysB*fastq" -type f
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

In the previous command, the two expressions were implicitly connected with a logical and: the resulting matches had to be regular files and also had to have zmaysB*fastq in the name. You can connect expressions explicitly using the -and operator…

find data/seqs -name "zmaysB*fastq" -and -type f
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

…or the -or operator:

find data/seqs -name "zmaysA*fastq" -or -name "zmaysC*fastq"
data/seqs/zmaysA_R1.fastq
data/seqs/zmaysA_R2.fastq
data/seqs/zmaysC_R1.fastq
data/seqs/zmaysC_R2.fastq

You can negate expressions with ! — though you must quote the ! so it doesn’t get evaluated by the shell:

# Find regular files that do NOT match "zmaysC*fastq"
find data/seqs -type f "!" -name "zmaysC*fastq"
data/seqs/zmaysA_R1.fastq
data/seqs/zmaysA_R2.fastq
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

If the quoted "!" looks cryptic, you can use the equivalent -not instead, which doesn’t need quotes:

find data/seqs -type f -not -name "zmaysC*fastq"

As another negation example, say you have some files with temp in their names that you don’t want to include in the find output:

touch data/seqs/zmays{A,C}_R{1,2}-temp.fastq

find data/seqs -type f "!" -name "zmaysC*fastq" -and "!" -name "*-temp*"
data/seqs/zmaysA_R1.fastq
data/seqs/zmaysA_R2.fastq
data/seqs/zmaysB_R1.fastq
data/seqs/zmaysB_R2.fastq

The output is identical to that of the previous command, even though four new -temp files now exist: the zmaysC ones were excluded by the first negated expression, and the zmaysA ones by the second.

NoteIf ! gets evaluated by the shell, then what does it do?

So what does a ! mean to the shell? It accesses past commands — for example, to re-execute your most recent command, use the following:

!!

5.4 Selecting files by size and last-modified date

With -size, you can select files by their size, using + for “larger than” and - for “smaller than”, and a k, M, or G suffix for kilobytes, megabytes, or gigabytes. For example, to find unusually large FASTQ files in the practice dataset:

find /fs/ess/PAS3493/people/$USER/garrigos/fastq -size +24M
/fs/ess/PAS3493/people/jelmer/garrigos/fastq/S71_R1.fastq.gz
/fs/ess/PAS3493/people/jelmer/garrigos/fastq/S71_R2.fastq.gz

A related option is -empty, which is handy to spot output files that were created but never filled, e.g. because an analysis step failed:

# (All the dummy files you created with 'touch' are empty, so this lists them all)
find data/seqs -type f -empty

With -mmin (minutes) and -mtime (days), you can select files by when they were last modified:

# Files modified less than 60 minutes ago:
find data/seqs -mmin -60

# Files modified more than 30 days ago:
find /fs/ess/PAS3493/people/$USER -type f -mtime +30

5.5 Running commands on find’s results

Now, say that you instead want to remove the temporary files we saw above. We can do this using -exec followed by the rm command (in this case, using rm -i for interactive removal):

find data/seqs -name "*-temp.fastq" -exec rm -i {} \;

Here, {} is the placeholder for the file names we are passing on, and you have to indicate the end of our command with an escaped semicolon: \;.

-exec can be very useful to process file queries that are more complicated than what a simple globbing pattern allows for. With -exec, you can use any command to operate on the files that you found.

Finally, note that for the common operation of deleting files, a shortcut exists:

find data/seqs -name "*-temp.fastq" -delete

6 xargs to repeat commands

xargs is to be read/pronounced as x-args, where “args” means “arguments”. This command passes arguments, supplied via standard in, on to another command. For example, first recreate the temporary files, then remove them with xargs:

touch data/seqs/zmays{A,C}_R{1,2}-temp.fastq

find data/seqs -name "*-temp.fastq" | xargs rm

The above command is equivalent to the following, where rm receives the very same list of files as its arguments:

rm data/seqs/*-temp.fastq

Unlike the glob, though, xargs won’t run into the argument list too long error: if the list of files is too long for a single command, xargs automatically splits it up and runs rm several times.

Two other useful xargs options are:

  • -I {} to put each item at a specific place in the command, e.g. when the file name should not be the last argument:

    mkdir -p backup
find data/seqs -name "*_R1.fastq" | xargs -I {} cp {} backup/

  • -P to run several commands in parallel, combined here with -n 1 to process one file per command:

    # Compress FASTQ files with gzip, up to 4 files at a time:
find fastq_dir -name "*.fastq" | xargs -n 1 -P 4 gzip

6.1 xargs versus find -exec

By using xargs instead of find -exec, you separate the process that finds the files you want to operate on, from the actual operations. This can be beneficial, such as when you want to carefully inspect a list of files before doing anything — for example:

  • Create some dummy files to practice on:

    touch data/seqs/zmays{A,C}_R{1,2}-temp.fastq

  • Save the find results in a text file:

    find data/seqs -name "*-temp.fastq" > files-to-delete.txt
cat files-to-delete.txt
    data/seqs/zmaysC_R1-temp.fastq
data/seqs/zmaysA_R1-temp.fastq
data/seqs/zmaysA_R2-temp.fastq
data/seqs/zmaysC_R2-temp.fastq

  • Now pass that list of files to rm:

    cat files-to-delete.txt | xargs rm

6.2 find | xargs and spaces in file names

As always, spaces in file names can trip you up — but you were promised a solution with find and xargs! However, out of the box, the below does in fact fail:

touch "samples A.txt"  "samples B.txt"

find . -name "samples [AB].txt" | xargs rm
rm: cannot remove './samples': No such file or directory
rm: cannot remove 'A.txt': No such file or directory
rm: cannot remove './samples': No such file or directory
rm: cannot remove 'B.txt': No such file or directory

The solution is to use -print0 with find, so it prints files with a “null byte” as the delimiter. Additionally, you need to tell xargs about the null-byte delimiter using -0:

find . -name "samples [AB].txt" -print0 | xargs -0 rm -v
removed './samples A.txt'
removed './samples B.txt'

    Put echo in front of the actual command:
