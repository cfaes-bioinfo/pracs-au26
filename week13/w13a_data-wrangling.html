1 Introduction

1.1 Overview & learning goals

One of R’s most powerful features is its built-in ability to deal with tabular data — i.e., data with rows and columns like those familiar from Excel spreadsheets and so on. R stores tabular data in a data structure called a “data frame”.

In this lecture, you will learn:

  • The vector data structure, R’s main data types, and comparisons (not tabular data)
  • How to read files with tabular data, and look at them in Positron’s Data Explorer
  • How to subset, sort, modify, and summarize data frames with dplyr functions
  • How to reshape and join data frames
  • How to write data frames to files

You’ll learn most of this by exploring the gene count table from the RNA-seq data set that you’ve been working with.

2 Vectors and data types

Before turning to tabular data, we’ll cover two of R’s nuts and bolts: the vector, which is R’s simplest data structure, and data types, which are how R distinguishes between different kinds of data, like numbers versus character strings.

2.1 Vectors

A vector in R is a collection of one or more items, which we’ll call elements. A common way to make a vector is with the c() (combine) function — for example, to store the number of RNA-seq reads for three genes:

read_counts <- c(500, 1200, 300)
read_counts
[1]  500 1200  300

A single value, like 500, is also a vector, with one element.

Next, let’s store the IDs of these genes:

gene_ids <- c("geneA", "geneB", "geneC")
gene_ids
[1] "geneA" "geneB" "geneC"

These IDs are character strings (strings for short):

  • Each string, like "geneA", constitutes one element, not 5 (its number of characters).
  • Unlike numbers, strings have to be quoted1. This doesn’t mean the quotes are part of the string itself: they are just a way to tell R that it is a string.

Recall that anything that is not quoted is interpreted as an object, like iris in the previous lecture. Therefore, the code below doesn’t work, because there is no object called geneA:

c(geneA, geneB, geneC)
Error:
! object 'geneA' not found

2.2 Vectorization

Consider the output of this command:

read_counts / 1000
[1] 0.5 1.2 0.3

Above, every individual element in read_counts was divided by 1000. This behavior, where an operation is automatically applied to every element of a vector, is called “vectorization” — a key feature of the R language.

Many functions are vectorized too, like log2(), which you can use to log-transform counts:

log2(read_counts)
[1]  8.965784 10.228819  8.228819

Other functions instead summarize a vector, like length() to get the number of elements, and mean() and sum() to compute the mean and sum:

length(read_counts)
[1] 3
mean(read_counts)
[1] 666.6667
sum(read_counts)
[1] 2000

For more functions like these, see the optional R self-study page.

Exercise 1: Vectorization

Longer genes get more reads simply because they are longer, so a common step in RNA-seq analysis is to divide read counts by gene length. Start by creating a vector with the lengths (in kilobases) of the three genes in read_counts:

gene_lengths_kb <- c(2, 4, 1.5)

What do you think the following code will return? We didn’t cover this kind of scenario, but go ahead and test your intuition!

read_counts / gene_lengths_kb
  1. 250 300 200
  2. 266.6667 (a single number)
  3. Nine numbers: each count divided by each gene length
  4. An error, because you can’t divide a vector by another vector

Self-study exercise: Gene lengths in base pairs

Now say that you have gene lengths in base pairs instead:

gene_lengths_bp <- c(2000, 4000, 1500)

Which of these computes the number of reads per kilobase for each gene, giving the same result as read_counts / gene_lengths_kb?

  1. read_counts / gene_lengths_bp
  2. read_counts / gene_lengths_bp / 1000
  3. read_counts / (gene_lengths_bp / 1000)

After you’ve decided, run all three lines and check if you were correct.

  Click to see the solution

c) is correct:

read_counts / (gene_lengths_bp / 1000)
[1] 250 300 200

Option a) computes the number of reads per base pair instead.

Option c) combines two kinds of vectorization: gene_lengths_bp / 1000 divides each length by the single number 1000, and the counts are then divided element-wise by the resulting lengths (the first count by the first length, and so on).

The parentheses matter: option b) is calculated from left to right, so it divides by 1000 instead of multiplying by it. (read_counts / gene_lengths_bp * 1000 does work.)

NoteExtracting elements from vectors (Click to expand)

Extracting elements from objects like vectors is often called “indexing”. In R, you can do this with square brackets [ ].

  • Get the second element with [2]2:

    gene_ids[2]
    [1] "geneB"

  • Get the first and third elements with [c(1, 3)]:

    read_counts[c(1, 3)]
    [1] 500 300

In other words, you extract elements from a vector by using another vector, whose values are the positions of the elements in the original vector.

2.3 Data types

R distinguishes between different kinds of data using several pre-defined “data types”, and its behavior depends heavily on the data type. For example, R refuses to perform mathematical operations on character strings:

gene_ids * 2
Error in `gene_ids * 2`:
! non-numeric argument to binary operator

You can ask what type of data something is with the typeof() function — keep in mind that vectors can only contain one data type, so this is the type of all elements in the vector:

typeof(gene_ids)
[1] "character"
typeof(read_counts)
[1] "double"

Here is an overview of R’s four common data types, including the abbreviations you’ll often see in R output (note that anything placed between quotes is a character — even plain numbers like "5"):

Data type Abbreviation Explanation Example
double / numeric dbl / num Numbers that can have decimal points 3.14
integer int Whole numbers 5L
character chr Character strings "geneA", "5"
logical lgl TRUE or FALSE (unquoted!) TRUE
NoteWhole numbers you type yourself are still stored as doubles (Click to expand)

For example:

typeof(5)
[1] "double"

To force R to store a number as an integer, you can add an L after it:

typeof(5L)
[1] "integer"

Numbers are also stored as integers when you create a series of whole numbers with the : operator:

1:3
[1] 1 2 3
typeof(1:3)
[1] "integer"
NoteWhat happens when you combine data types in one vector? (Click to expand)

Because a vector can only contain a single data type, R silently converts mixed data to the same type — for example, numbers to strings:

mixed <- c(500, 1200, "300")
mixed
[1] "500"  "1200" "300" 
typeof(mixed)
[1] "character"

This so-called type coercion can be the source of surprises: for example, if a single value in a column of numbers in a file is not a number, R will read the whole column as character.

2.4 Comparing things

R returns logicals when you compare things:

10 > 6
[1] TRUE

Comparisons are vectorized too, so you get a TRUE or FALSE for each element — for example, to check which genes have more than 400 reads:

read_counts > 400
[1]  TRUE  TRUE FALSE

Logicals can be used as if they were numbers, where TRUE represents 1 and FALSE represents 0. This provides an easy way to count how many elements meet a condition, like the number of genes with more than 400 reads:

sum(read_counts > 400)
[1] 2

Here are the most common comparison operators in R:

Operator Description Example
> Greater than 5 > 6 returns FALSE
< Less than 5 < 6 returns TRUE
== Equal to 10 == 10 returns TRUE
!= Not equal to 10 != 10 returns FALSE
>= Greater than or equal to 5 >= 6 returns FALSE
<= Less than or equal to 6 <= 6 returns TRUE

3 Data frames

3.1 What is a data frame?

Data frames are another R data structure, which can be thought of as vectors pasted side-by-side: each column is a vector, and can therefore only contain one data type. This also means that rows and columns are not equivalent: each column is a variable, and each row an observation.

3.2 The tidyverse

To work with data frames, we’ll use a family of R packages designed for “dataframe-centric” data science called the “tidyverse” . Dataframe-centric refers to doing most if not all data analysis while keeping the data in a data frame.

All core tidyverse packages can be installed and loaded with a single command. You installed the tidyverse at the end of last week’s lecture, so you only need to load it now:

library(tidyverse)

TipWhy you get a warning about “Conflicts” (Click to expand)

When you loaded the tidyverse, the output included a “Conflicts” section that may have seemed ominous:

── Conflicts ────────────────────────────────────────── tidyverse_conflicts() ──
✖ dplyr::filter() masks stats::filter()
✖ dplyr::lag()    masks stats::lag()
ℹ Use the conflicted package (<http://conflicted.r-lib.org/>) to force all conflicts to become errors

What this means is that two tidyverse functions, filter() and lag(), have the same names as two functions from the stats package that were already in your R environment.

Those stats package functions are part of what is often referred to as “base R”: core R functionality that is always available (loaded) when you start R.

Due to this function name conflict/collision, the filter() function from dplyr “masks” the filter() function from stats. Therefore, if you write a command with filter(), it will use the dplyr function and not the stats function.

You can use a “masked” function, by prefacing it with its package name as follows: stats::filter().

3.3 Today’s key tidyverse functions

The dplyr and tidyr packages, both part of the tidyverse, provide functions to manipulate data in data frames, such as for “data wrangling”: cleaning and transforming your data to make it easier to visualize and analyze. In this lecture, we’ll cover some of the most commonly used functions from these packages:

  • Subsetting:
    • select() to pick columns (variables)
    • filter() to pick rows (observations)
  • Reshaping:
    • pivot_longer() to reshape a data frame from wide to long format
  • Transforming:
    • summarize() to compute across-row summaries
    • mutate() to modify values in columns and create new columns
    • arrange() to change the order of rows (i.e., to sort a data frame)
  • Combining:
    • left_join() to combine two data frames based on one or more shared columns

All these functions have the same straightforward input/output behavior:

  • Their input is a data frame.
  • Their output is a new, modified data frame. The input data frame itself is not changed, unless you assign the output back to it.

Finally, we’ll see how to read and write data frames to and from TSV files with read_tsv() and write_tsv() from the readr package.

4.3 Columns are vectors

To get a data frame’s dimensions, use nrow() for the number of rows, ncol() for the number of columns, or dim() for both:

dim(counts)
[1] 18855    24

You can extract individual columns from a data frame using the $ operator. This returns a vector, so let’s use head() to show only its first elements:

head(counts$S63)
[1] 10275.414958     3.853383 88041.022158  8749.043468 55772.448541
[6] 38543.324458

Like any vector, you can compute with it — for example, to get the total number of counts for sample S63:

sum(counts$S63)
[1] 24297227

This total is called the library size of a sample. You could compute it like this for each of the 22 samples, but below, you’ll learn a better way.

5 Subsetting data frames

5.1 select() to pick columns (variables)

The select() function subsets a data frame by including/excluding certain columns. By default, it only includes the columns you specify — for example, to get the gene IDs and the counts for two samples:

select(.data = counts, gene_id, S64, S63)
# A tibble: 18,855 × 3
   gene_id           S64      S63
   <chr>           <dbl>    <dbl>

 2 ATP8             2.92     3.85

 4 COX2          7925.    8749.

 6 CYTB         36352.   38543.

10 LOC120412326     3.97    12.0 
# ℹ 18,845 more rows

Output columns appear in the order in which you listed them within select(), so this function allows you to also reorder columns.

Two other things are worth noting about this command, which are true for most other dplyr functions:

  • Each column name is a separate, unnamed argument to select(), so you don’t combine them with c().
  • Column names are not quoted, even though you learned that R treats unquoted names as objects. This is meant as a convenience, but can be confusing at first.

You can also specify columns that should be excluded, by prefacing their name with a !. In this file, the gene_name column is identical to gene_id, so let’s remove it, and assign the result back to counts:

counts <- select(.data = counts, !gene_name)

5.2 filter() to pick rows (observations)

The filter() function outputs only those rows that satisfy one or more conditions — for example, to get the counts for the mitochondrial gene ATP6:

filter(.data = counts, gene_id == "ATP6")

5.3 The pipe (|>)

It’s common to use several consecutive dplyr functions to wrangle a data frame into the format you want. For example, you may want to first filter() rows, and then select() columns. You could do that as follows:

counts_atp6 <- filter(.data = counts, gene_id == "ATP6")

select(.data = counts_atp6, gene_id, S63, S64)
# A tibble: 1 × 3
  gene_id    S63   S64
  <chr>    <dbl> <dbl>
1 ATP6    10275. 8255.

You could go on like this, with a separate command for each step, and successively creating new, intermediate objects. In the Unix shell, we used the pipe | to shorten code and avoid writing intermediate files. Since 2021, R also has a pipe operator, |>. So in R, the vertical bar | is followed by a greater-than sign >.

Let’s start by seeing a rephrasing of the code above, now using pipes:

counts |>
  filter(gene_id == "ATP6") |>
  select(gene_id, S63, S64)
# A tibble: 1 × 3
  gene_id    S63   S64
  <chr>    <dbl> <dbl>
1 ATP6    10275. 8255.

Above, we took the counts data frame, sent (“piped”) it into the filter() function, whose output in turn was piped into select(). Just like in the Unix shell, you can think of the pipe as “then”: take counts, then filter, then select.

Also like in the Unix shell, when using the pipe, you no longer specify an input argument for the function, because it now gets its input data via the pipe3. Using pipes involves less typing and is more readable than successive assignments.

TipPipe tips
  • In R (unlike in the shell), it’s good practice to start a new line after a pipe |>, and to keep the subsequent line(s) indented.
  • You can also insert a pipe with the keyboard shortcut Ctrl/Cmd + Shift + M.
  • In code online, you may also often see an older pipe symbol, %>%, which works the same in most cases4.
NoteSide-by-side: the pipe in the shell and in R (Click to expand)

In both languages, the input moves from inside the command to the left of the pipe with vs. without the pipe:

Shell

# Without: the file is an argument
wc -l metadata.tsv
# With: wc gets its input via the pipe
cat metadata.tsv | wc -l

R

# Without: the data frame is an argument
filter(.data = counts, gene_id == "ATP6")
# With: filter() gets its input via the pipe
counts |> filter(gene_id == "ATP6")

6 Reshaping data frames

6.1 Tidy data

The tidyverse is named after the concept of “tidy data” (Wickham 2014), a way of organizing tabular data that follows three rules:

  1. Each variable is a column.
  2. Each observation is a row.
  3. Each value is a cell.

For example, the following table with plant height measurements is not tidy, because the time point variable is spread across two column names:

plant height_7dpi height_14dpi
P1 10.2 15.1
P2 9.8 14.3

Here is the same data in tidy form, with separate columns for the time point and the height:

plant dpi height
P1 7 10.2
P1 14 15.1
P2 7 9.8
P2 14 14.3

Our count table is not tidy either: each sample is in a separate column. One observation is the count of one gene in one sample, so right now we have many observations per gene in a single row.

This “wide” format is the standard way to store count tables, and it is what we’ll need for the differential expression analysis in week 15. But because tidyverse functions are designed to work with tidy data, it is often easier to reshape data into a “long”, tidy format first.

TipOrganizing your spreadsheet data: tidy or not? (Click to expand)

Organizing your own data in tidy form from the start will make your analyses easier. That said, a wide format can be more convenient for entering data, for example when you add a column after each measurement round. That is fine, since you can reshape data in R, as you’ll see next.

6.2 pivot_longer() to go from wide to long

The pivot_longer() function from the tidyverse’s tidyr package turns a wide data frame into a long one:

counts_long <- counts |>

    names_to = "sample_id", # new column with the old column names
    values_to = "count" # new column with the values
  )

9 Writing to files

To write a data frame to a TSV file, you can use the write_tsv() function, with argument x for the R object and argument file for the file path — for example, to save the library sizes:

write_tsv(x = lib_sizes, file = "lib_sizes.tsv")

If you want to take a look at the file you just created, find it in the Explorer and click on it. Positron opens CSV and TSV (and even Excel) files in the Data Explorer, just like a data frame:

This is a quick way to look at any data file without reading it into R, for example to check its column names before you read it. To see the plain text instead, click the “Open as Plain Text File” button at the top of the Data Explorer.

10 Recap

  • A vector is a collection of elements of a single data type (character, double, integer, or logical).
  • Operations on vectors are vectorized: they happen for each element.
  • Comparisons return logicals, and sum() on these counts the TRUEs.
  • read_tsv() and write_tsv() read and write TSV files.
  • dplyr functions like filter() and summarize() manipulate data frames, and the pipe |> chains them together.
  • pivot_longer() reshapes a wide data frame into a long one, and left_join() combines data frames.
