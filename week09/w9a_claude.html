1 Introduction

1.1 Learning goals

In this lecture, you will learn how to:

  • Set up and use the Claude Code extension in VS Code Server at OSC
  • Use Claude to ask questions about, write, and edit code, with your files as context
  • Let Claude act as an “agent” that runs commands, and control what it may do with permission modes
  • Give Claude persistent instructions (ones that carry over between conversations) with a CLAUDE.md file
  • Keep a record of your AI use, with exported conversations and an AI diary
  • Manage Claude’s context window and costs

1.2 From chat to agents

In the previous lecture, you used genAI through a browser-based chat. That works well for many questions, but when coding, it has clear limitations: the model can’t see your files unless you paste or upload them, and it can’t check whether the code it writes actually works.

Today, we’ll use Claude Code, Anthropic’s “agentic” coding tool. Working inside your editor, it can:

  • Read the files in your project, so you don’t have to explain or paste them
  • Edit and create files, showing you each change for approval
  • Run commands in the terminal, for example to test a script or check a program’s help info

In other words, if browser chat is like emailing a knowledgeable colleague, working with an agent is more like having them sit next to you at your computer.

1.3 Why Claude Code in VS Code?

There are many AI coding tools, but this setup has two key advantages for us:

  • It’s approved for your research data.
    Rather than using a personal account, we’ll authenticate through an API key from OSU’s Generative AI Service , which is approved for use with restricted institutional data.

  • It integrates with our current VS Code setup.
    It only takes one extension, which you installed last week.

NoteCode completions, GitHub Copilot, and other forms of Claude Code

Another kind of AI coding help in IDEs is code completions: suggestions that appear in the editor as you type, and that you can accept with Tab. These either add new code (“ghost text” suggestions) or change code you already wrote (“next edit” suggestions). Claude Code does not offer code completions, but some other tools do, like GitHub Copilot. GitHub Copilot is built into VS Code, including VS Code Server at OSC. If you want to try code completions, see the self-study page on GitHub Copilot.

Claude Code itself also comes in several forms, including a command-line program and a desktop app. Here, we’ll use its VS Code extension.

NoteMore about the settings file (Click to expand)

Here is what the file looks like before you add your own key:

~/.claude/settings.json
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://litellm.cloud.osu.edu",
    "ANTHROPIC_AUTH_TOKEN": "<API-KEY>",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-5-5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-sonnet-5",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-haiku-5-5",
    "CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS": "1"
  },
  "model": "sonnet",
  "effortLevel": "medium",
  "outputStyle": "Concise",
  "theme": "auto"
}

The file is in JSON format, a plain-text format with key-value pairs: a colon : separates each key from its value, pairs are separated by commas, and curly braces {} group pairs. A single missing quote or comma breaks the whole file (this would be a likely culprit if Claude doesn’t pick up your API key).

  • ANTHROPIC_BASE_URL makes Claude go through OSU’s service rather than directly to Anthropic.
  • ANTHROPIC_AUTH_TOKEN is the API key.
  • The MODEL lines specify which model versions to use.
  • model and effortLevel set the default model (Sonnet) and effort level (Medium).
  • outputStyle makes Claude’s answers shorter and more to the point (remove this line if you prefer longer explanations).
ImportantTreat the API key like a password

Anyone with your key can use it, and usage costs money and depletes your key’s budget. So never share your key or commit it to a Git repository. That’s one reason the settings file is located in your Home dir, and not in a project dir that others can see.

3 Basics of the interface

3.1 The prompt box

Most of what you’ll do with Claude starts from the prompt box:

We’ll go over the other buttons across the bottom of the box in more detail below — but briefly, from left to right:

  • + adds files as context to your prompt.
  • / opens the so-called command menu, which is really a collection of nearly all options and settings in Claude Code, including those that can be accessed with the other buttons. You’ll need this one least often.
  • Once Claude has responded, a clock icon with a number of minutes appears. This shows how long until the conversation’s “cache” expires, after which your next message will be more expensive.
  • Sonnet 5 Medium is the current model and effort level. Keep it at that for now, and don’t select “Default (recommended)”, which switches to the much more expensive Opus.
  • Manual is the current permission mode (what Claude is allowed to do), and you can click on it to change it.

    Click here for a possible script

    It’s likely that it will loop over files with "$@", which is a special variable that expands to all arguments given to the script. This is really handy when you don’t know how many files will be given to the script.

    scripts/count_reads.sh

# Usage: count_reads.sh <fastq.gz> [fastq.gz ...]

# Loop over all FASTQ files given as arguments ("$@").
for fastq_file in "$@"; do

5 Your files as context

5.1 Your workspace is the context

A key advantage of using AI inside your editor is that your files are readily available: you don’t need to upload or copy-and-paste them. Your entire workspace (the folder open in VS Code) is “implicit” context: when Claude thinks it’s useful, it will search and read files there by itself.

However, when you have a specific task and specific files in mind, it’s often better to point Claude to the relevant files explicitly. That’s faster and cheaper, and avoids Claude making assumptions about which files you mean.

5.2 Adding files and code to your prompt

  • The file that’s active in the editor is added automatically. You can see this below the prompt box (to remove the file as context, click the x next to it).

    Because count_reads.sh is the active file in the editor, it’s been automatically added as context to the prompt.

  • Selected lines in the editor are also added automatically. This is handy to ask about specific lines in a longer script:

  • Type @ followed by part of a file name to add any file in your workspace, including files in subdirs. You can also wait for the list to appear after typing @, as shown in the screenshot below.

  • When you switch to a different file in the editor, the automatically added file is swapped for the new one, so the previous file is no longer attached to your next prompt (though anything Claude already read is still part of the conversation). To add multiple files, type @ (see above), or press Alt/Option+K while in a file: this inserts an @-mention of that file (or of the selected lines) into your prompt, so it stays in context when you switch to another file.

NoteThe + button (Click to expand)

You can also add context with the + button below the prompt box. This also lets you upload files from your own computer.

6 Permission modes and running commands

6.1 Permission modes

The permission mode, shown at the bottom right of the prompt box, determines what Claude may do without asking you first. Click on it to switch between modes:

  • Manual: Claude asks permission for each file edit and for many commands (it runs simple read-only commands, like ls, head, and grep, without asking, as you should have noticed in the previous exercises).

  • Edit automatically: Claude edits files without asking, but asks about running commands just like in Manual mode.

  • Auto: a separate AI model checks each action, whether it involves editing files or running commands, and Claude only asks you for permission for risky ones (see the box below).

  • Plan: Claude only writes a plan, which opens as a Markdown document that you can review and modify before Claude carries it out. This is useful for bigger tasks and is covered in more detail in the self-study page on Claude Code.

TipFor now, we’ll stick to Manual mode

It’s slower-going, but you’ll see exactly what Claude does. Once you’re comfortable reviewing Claude’s work, though, the many permission requests can become tedious, and it’s easy to start clicking “Yes” without really reading what you approve.

At that point, “Auto mode” is a good alternative: routine actions, like editing files in your project, are then permitted without asking, while risky ones, like deleting many files or doing things you didn’t ask for, are blocked.

6.2 Letting Claude run commands

    scripts/read_summary.sh

# Copy the placeholder variables

outfile="$2"

# Initial logging

    Then watch what Claude does:

Click here for a partial solution

The script contains two errors:

  • The glob in the for loop is inside double quotes ("$fastq_dir/*.fastq.gz"), so it is not expanded. The loop therefore runs only once, with the literal string ../garrigos/fastq/*.fastq.gz, and cat fails because no file has that name. The fix is to keep the * outside the quotes: "$fastq_dir"/*.fastq.gz.

  • The script uses cat instead of zcat on gzipped files. This doesn’t cause an error message: wc -l simply counts the “lines” in the compressed data, so the script reports read counts that are far too low. This is the more dangerous of the two errors, because it silently produces wrong results.

Claude may have noticed the second error by reading the script, after running it and seeing suspicious read counts, or not at all. This shows why a script that runs without errors still needs to be checked, whether you or Claude wrote or fixed it.

Finally, because the script appends (>>) to the output file, running it multiple times will add the same files again to read_summary.txt. Claude may have noticed this when testing the script, and either removed the file between test runs or changed >> to something else.

7 Persistent instructions with CLAUDE.md

7.1 Why persistent instructions?

Each new conversation with Claude starts with an empty context window: it doesn’t see what you discussed in earlier conversations. So you may find yourself repeatedly telling it the same things, such as:

  • “Run programs with Apptainer containers, not by installing them”
  • “Never modify the raw data in ../garrigos”
  • “Follow these script conventions: …”

Rather than constantly repeating yourself, and having to write long prompts, you can put these kinds of instructions in a file called CLAUDE.md to make them “persistent” across conversations.

7.2 What is CLAUDE.md, and what to include in it

CLAUDE.md is a Markdown file that Claude automatically reads at the start of every conversation in your project. There is no required format, but it should be concise and easy to read, for you as well as for Claude4. Typically, it’s placed in a project’s root dir, like our week09 dir:

week09
├── CLAUDE.md
└── scripts
    ├── count_reads.sh
    ├── fastqc_all.sh
    └── fastqc.sh

Some useful things to include in a CLAUDE.md are:

  • Project overview: the research question, organism, data type, and experimental design.
  • Project file structure: where the raw data, scripts, and results are.
  • Conventions: how you write scripts and name files.
  • Software: how software is run (e.g., with containers) and which versions.
  • Rules and pitfalls: things Claude should never do, or tends to get wrong.
NoteDrafting a CLAUDE.md with /init (Click to expand)

Instead of writing a CLAUDE.md from scratch, you can type the /init command in the prompt box: Claude then looks through your project and drafts a CLAUDE.md for you to review and edit. (If a CLAUDE.md already exists, /init will instead suggest updates to it.)

This can be a useful start in a larger existing project. But in a small project like our week09 dir, /init doesn’t have much to work with, so its draft would mostly describe the existing scripts — information Claude can also get by simply reading those scripts when needed. Even in larger projects, the most valuable parts of a CLAUDE.md are things only you know: what the project is about, where the data is, and how you want things done.

The final script is quite good, and has some nice little explanations in the comments:

scripts/subset_fastq.sh
#!/bin/bash
set -euo pipefail

# Extracts the first N reads from a gzipped FASTQ file
# Usage: bash scripts/subset_fastq.sh <FASTQ file> <output dir> <number of reads>

# zcat/head/gzip are standard coreutils already present on the system,
# so no Apptainer container is needed here

# Copy the placeholder variables
fastq="$1"
outdir="$2"
n_reads="$3"

# Initial logging
echo "Starting script subset_fastq.sh"
date
echo "Input FASTQ file:   $fastq"
echo "Output dir:         $outdir"
echo "Number of reads:    $n_reads"
echo

# Create the output dir if needed
mkdir -p "$outdir"

# Each FASTQ read spans 4 lines, so N reads = N*4 lines
n_lines=$(( n_reads * 4 ))

# Output file keeps the input's base name
outfile="$outdir"/$(basename "$fastq")

# Decompress, take the first n_lines lines, and re-compress.
# zcat is wrapped in "|| true" because head stops reading before zcat is done,
# which would otherwise make zcat exit with an error (SIGPIPE) under "set -o pipefail"
(zcat "$fastq" || true) | head -n "$n_lines" | gzip > "$outfile"

# Final logging
echo
echo "Output FASTQ file:  $outfile"
echo "Successfully finished script subset_fastq.sh"
date

One caveat: || true hides any zcat error, not just the harmless one. For example, if the input file doesn’t exist, the script creates an empty output file and still reports success.

NoteMore on using CLAUDE.md (Click to expand)

Keep updating your CLAUDE.md
Start simple, and add to it whenever you notice yourself telling Claude the same thing again, or Claude making the same mistake again. Be mindful of its length, though: it’s read at the start of every conversation, so it uses up tokens each time.

Other locations for CLAUDE.md files
You can also put a CLAUDE.md in a parent dir, to apply to several related projects, or at ~/.claude/CLAUDE.md, to apply to all your projects. See the documentation on CLAUDE.md for details.

Instructions are not strict rules
CLAUDE.md contains instructions, which Claude will usually but not always follow. To strictly enforce rules, use permission rules. For instructions that you only need for specific tasks, see the self-study page on skills.

CLAUDE.md vs. Claude’s memory
Besides reading your CLAUDE.md, Claude also keeps memory notes for itself: when you correct it or tell it about your preferences, it may save a note, which is loaded into future conversations in the same project. You can also ask it directly to save memories, e.g. “Remember that I prefer …”. Like CLAUDE.md, memory notes are plain Markdown files, and they’re stored in your Home dir. Claude writes them itself, but it’s worth checking them now and then.

More broadly, memory notes are another big advantage of AI in your editor. While browser-based chatbots may remember general things about you, here you can save more extensive, specific information about your project and your preferences. You can check Claude’s memory notes by typing /memory in the prompt box. More details are on the self-study page.

NoteAutomatically saving all conversations (Click to expand)

Exporting by hand is easy to forget. To save every conversation automatically, you can use a “hook”: a shell command that Claude Code runs at a specific moment, such as whenever Claude finishes responding. scripts/count_reads.sh
#!/bin/bash
set -euo pipefail

# Count the number of reads in one or more FASTQ files and print the
# result as a tab-separated table.
# Usage: bash scripts/count_reads.sh <fastq.gz> [fastq.gz ...]

echo -e "file\tn_reads"

# Loop over all FASTQ files given as arguments ("$@").
for fastq_file in "$@"; do

    num_lines=$(zcat "$fastq_file" | wc -l)

done

9 Managing context and cost

9.1 Agents fill up the context window quickly

Recall from the previous lecture that a model’s context window holds everything in the conversation, and that performance degrades as it fills up. With an agent, this happens much faster than with a chatbot: every file Claude reads and every command output it sees goes into the context too.

The size of the context window depends on the model. Current Claude models can hold up to 1 million tokens (very roughly 750,000 words), but some models and setups use a smaller window of 200,000 tokens.

To see how full the context window is, type /context in the prompt box. At the top, this shows which model you’re using, and how many tokens are in use out of that model’s context window size.

NoteAbout the context categories (Click to expand)

These categories are shown in the screenshot above:

  • System prompt: Claude Code’s built-in instructions, the same in every conversation.
  • Memory files: your CLAUDE.md file(s), which are listed below the table, and Claude’s own memory notes, if any.
  • Skills: short descriptions of available “skills” (see this optional material to learn more about skills).
  • Messages: everything in the conversation so far, including files Claude read and command output it saw. This grows as the conversation moves along: in every turn (new prompt and response), all previous messages are sent to the model again along with your new prompt, so each turn processes more tokens than the one before (see the box on caching below).
  • Autocompact buffer: space reserved for summarizing the conversation once the context window is nearly full (see /compact below).
  • Free space: what’s left.

Depending on your setup, you may also see other categories, like System tools: descriptions of the tools Claude can use, like reading files.

TipCaching: what gets reprocessed with every message (Click to expand)

Models don’t remember anything, not even between individual rounds of prompts and answers (“turns”) in a conversation.

With every new prompt, the entire context (the system prompt, your CLAUDE.md, and all earlier messages, including files Claude read and command output) is sent to the model again and processed as input tokens.

To make this faster and cheaper, the part of the context that hasn’t changed since the previous turn is cached: temporarily stored, so that it doesn’t need to be fully reprocessed. Cached input tokens cost only a fraction of the regular price (for Sonnet, about one tenth). Only your new prompt and everything Claude does in response are processed at the full price.

However, the cache expires after it hasn’t been used for a while, and it’s specific to a model. After the cache expires or when you switch models, the next message reprocesses the entire conversation at the full price.

With an API key like ours, the cache expires after only 5 minutes without activity. The clock icon in the prompt box (e.g., 4m) shows how much time is left. (With a personal subscription, Claude Code keeps the cache for an hour instead: that costs more per cached token, which doesn’t matter with a fixed monthly fee but does when you pay per token.)

Some practical consequences:

  • When you come back to a long conversation after a break of more than a few minutes, consider starting a new conversation instead, unless you really need what was discussed before.
  • Choose your model at the start of a conversation, rather than switching back and forth during it.
  • Even with caching, every turn in a long conversation costs more, sometimes significantly more, than one in a short conversation, which is another reason to start fresh often.

9.2 Start fresh often

Throughout this session, we’ve started a new conversation for each new task. That’s a good habit: Claude can get confused when you switch topics within a conversation, and a long conversation is slower and more expensive.

In a new conversation, Claude is at least in principle completely unaware of what was said in earlier ones. However, it does read your CLAUDE.md and its own memory notes, and it may read files like a diary (as discussed above), either on its own or because CLAUDE.md tells it to.

NoteThe /clear and /compact slash commands (Click to expand)

Two slash commands related to this:

  • /clear (or /new) also starts a new conversation. It may look like it deletes the current conversation, because it doesn’t visibly switch to a new one like the new-conversation icon does, but the previous conversation is still available under the clock icon.

  • /compact replaces the conversation so far with a summary, to free up space. Claude also does this automatically when the context window is nearly full. This is useful and clever behavior, though details can get lost in the process.

9.3 Models and effort levels

Click on Sonnet 5 Medium in the bottom-right of the prompt box to open the model and effort menu:

Models — The checkmark shows the model you’re currently using. Claude comes in four model “tiers”, listed here from most to least capable:

  • Opus: very capable, but slower and more expensive than Sonnet. Can be worth it for more complex questions. Generally avoid for this course.

Note“Ultracode” and “Thinking” toggles (Click to expand)

Ultracode
A brand-new toggle that is separate from the effort level. When it’s on, Claude handles every substantial task with a so-called “workflow”: a script that runs many Claude “subagents” in parallel, for example one per file, plus agents that double-check each other’s work. This is meant for large jobs such as auditing or modifying hundreds of files, and it makes each request use many more tokens and take longer.

Thinking
Earlier versions of Claude Code had a separate toggle to turn “thinking” on or off, and you may still see it in online tutorials and videos. This toggle has disappeared because recent Claude models always think, and decide for themselves how much thinking each step needs. The effort level is now the way to control this: a lower effort level means less thinking, and a higher one means more.

9.4 Cost

Every token costs money, and your API key has a limited budget: an initial $10, which we may increase later in the semester if needed. That may sound like a lot, but even a basic question often costs tens of cents, and a longer agentic task considerably more.

Once the budget is used up, Claude will reply with a message like that shown below — if that happens, let us know.

Besides your choice of model and effort level (see above), some other things to know about costs of your conversations:

  • Output tokens (Claude’s responses, including its “thinking”) cost several times more than input tokens.
  • Agentic tasks can use many tokens, even when the visible conversation is short, because Claude reads files and command outputs behind the scenes (see also the section on context windows above).
  • Large data files: Claude Code limits how much of a file or command output it takes in at once, and it’s smart about using commands like head and grep to look at data files. Still, large data files can quickly fill up the context window and cost a lot, so don’t ask it to “read” them5.

(When you have a personal subscription, more detailed usage information is provided.)

NoteAPI pricing vs. personal subscriptions (Click to expand)

Paying per token through an API key, as we do here, is much more expensive than a personal subscription to a service like Claude, which has a fixed monthly fee. A day of heavy agentic coding through an API can easily cost more than a month’s subscription.

If you want to try Claude for personal projects (and/or projects that don’t involve institutional data), a personal subscription is worth considering for this reason — though it will then be you who’s paying.

NoteUsing a personal account in a research project (Click to expand)

Personal accounts are not approved for institutional data, which includes your unpublished research data. But much of what an AI agent helps you with only involves your code. So you may be able to use a personal account in a research project, as long as you make sure that the AI can’t see your data:

  • Make Claude ignore files with a deny rule (see permission rules), such as "Read(//fs/ess/PAS1234/myproject/data/**)". This blocks Claude’s own file reads as well as common commands like cat and head, but not, for example, a script that opens the files by itself.

  • Keep your data outside the workspace. Claude reads files in your workspace without asking, but asks for permission before accessing anything outside of it. This is at odds with our recommendation to keep everything for a project in one self-contained project dir, which you then open as your workspace. But you can keep that project structure and open only a subdir as the workspace: for example, open myproject/scripts rather than myproject, and decline any request to access myproject/data. The downside is that Claude can then also not freely see the rest of your project, such as your results and README.

Keep in mind that anything that ends up in the conversation is sent to the AI, including the output of commands it runs (e.g. a script that prints part of your data) and anything you paste into a prompt. And none of the above is watertight. When in doubt, check with your advisor, or use an OSU-approved tool.

10 Good habits when working with an agent

Getting good help

  • Be explicit. Point Claude to the relevant files, and put your conventions and rules in CLAUDE.md.
  • Start fresh for each new task, and keep conversations focused.
  • Use it to raise your standards. Ask it for things that make code more robust but are easy to skip, like input checks, usage messages, comments, and a README (King et al. 2026).

Checking and keeping the results

  • You own the result. Read every proposed edit and command before approving it.
  • Verify, don’t trust. When Claude says something “works”, that may be a prediction rather than a test result. Run the code yourself, and check results independently.
  • Results should come from code you can rerun. Let Claude help you write code that you review, run, and keep; don’t rely on numbers or conclusions it only reports in the chat.
  • Commit before, review after. Use Git so that you can see and undo what Claude changed.
  • Keep a record. Commit the code that Claude helped write, and document how you used AI, for example with exported conversations and a diary. You can’t count on getting the same answer if you ask again later.

Protecting secrets and data

  • Keep secrets out of prompts. Never paste passwords or API keys into a prompt.
  • Remember that Claude can see what you can see. In shared dirs like /fs/ess/PAS3493, that may include other people’s files and data. Keep Claude’s workspace limited to your own project.
TipYou don’t always need an agent

For general questions, like explaining a concept or a command, a browser-based chat like Gemini (through your OSU account) works just as well and doesn’t use your API key’s budget. Use Claude when it helps that it can see your files and run commands.

If you do ask Claude Code simpler questions that don’t require it to read files or run commands, it sometimes helps to explicitly tell it to “answer from your general knowledge” or “don’t read any files”.

TipUse Git as a safety net (Click to expand)

Version control pairs very well with agentic AI: commit your work before asking Claude for a bigger change, review all of its changes afterwards with git diff or the Source Control panel, and undo anything you don’t want with git restore <file>. For more on this and other guardrails, such as permission rules that block specific actions, see the self-study page on Claude Code.
