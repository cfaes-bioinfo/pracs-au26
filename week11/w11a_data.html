3 File transfer to and from OSC

3.1 Overview of transfer options

In week 2, you learned that you can upload and download files from OSC in the OnDemand Files menu1. However, this method is only suitable for relatively small transfers. Here is a table with the main methods to transfer files between your computer and OSC, including ones that you can use for larger transfers:

Method Transfer size CLI or GUI Ease of use Flexibility/options
OnDemand Files menu smaller (<1GB) GUI Easy Limited
Remote transfer commands (e.g. scp, rsync) any CLI Moderate Extensive
SFTP clients (e.g. FileZilla) any GUI Easy Moderate
Globus larger (>1GB) GUI Moderate Extensive

Below, we’ll practice with scp. The other options are covered on the SSH and file transfer reference page, which also shows how to avoid typing your OSC password for every transfer.

3.2 Transfer with scp

We’ll try the scp (secure copy) command, which works much like cp, but can copy files between computers. It works for transfers of any size, and because it’s a command, you can keep a record of your transfers, e.g. in a README file.

So far in this course, you’ve always used a terminal in VS Code at OSC. To transfer files between your computer and OSC, you instead run scp in a terminal on your own computer — and that goes for both directions: downloads and uploads.

scp syntax

scp has the same basic syntax as cp, but you need a prefix to refer to a remote path. To refer to a path at OSC, you start with your username, @, and OSC’s address for file transfers, sftp.osc.edu, followed by : and then the path:

  • Download — copy from OSC to your computer:

    scp <user>@sftp.osc.edu:<remote-path> <local-path>

    For example, to download a file to your current working dir (.) on your computer:

    scp jelmer@sftp.osc.edu:/fs/ess/PAS3493/data.txt .

  • Upload — copy from your computer to OSC:

    scp <local-path> <user>@sftp.osc.edu:<remote-path>

    For example:

    scp data.txt jelmer@sftp.osc.edu:/fs/ess/PAS3493/

For paths at OSC, use absolute paths: scp doesn’t know your working dir in VS Code at OSC, so relative paths there are interpreted relative to your Home dir. And like with cp, use the -r option to copy dirs.

Trying scp

We’ll practice with small files, but keep in mind that you can use the same approach for much larger files that you can’t up/download via the OnDemand file browser, such as your raw FASTQ files.

  1. Open a terminal on your own computer

    • On a Mac, open the “Terminal” app (e.g. search for it with Cmd+Space).
    • On Windows, open the “Terminal” app (search for “terminal” — older versions call it “Windows Terminal”). Its tab will say “Windows PowerShell”: this is expected, because it runs the PowerShell shell rather than Bash. The commands in this section work the same in PowerShell.

  2. Navigate to the Downloads dir on your own computer
    This dir is in the same place on Mac and Windows computers:

    cd ~/Downloads

  3. Download a file
    Let’s download a FastQC report (replace jelmer with your username):

    scp jelmer@sftp.osc.edu:/fs/ess/PAS3493/share/week07/results/fastqc/S63_R1_fastqc.html .

    The first time you connect, you’ll get a message that “The authenticity of host ‘sftp.osc.edu’ can’t be established”, and a question if you want to continue connecting: type yes and press Enter 2.

    Next, you’ll be prompted for your OSC password. When you type it, no characters or *s will appear on the screen! You’ll have to enter your password for every scp command, unless you do these optional steps.

    ImportantAre you on Windows and can’t type “Yes”? (Click to expand)

    This seems to happen in the standalone PowerShell window, which has no tabs and usually a dark-blue background, but not in the Terminal app, which has tabs and a + at the top.

    If you can’t get the Terminal app to work, you can skip the question about host authenticity altogether by adding -o StrictHostKeyChecking=accept-new to your first scp command:

    scp -o StrictHostKeyChecking=accept-new jelmer@sftp.osc.edu:/fs/ess/PAS3493/share/week07/results/fastqc/S63_R1_fastqc.html .

    This has the same effect as typing yes, so you won’t need this option in later commands.

  4. Check the downloaded file
    Find the file in your Downloads folder in Finder (Mac) or File Explorer (Windows), and open it.

4 Downloading files at the command line

When you need to get large files from public repositories like NCBI (e.g. reference genome files, raw reads from the SRA), I recommend downloading them directly to OSC, using commands (instead of downloading to your own computer and then transferring to OSC). Not only is this quicker once you know how to, it is also much more reproducible: in your Markdown documentation files, you can store the exact commands used to obtain the data.

4.1 The wget command

You can download files from a URL using the wget command. It has many options, but basic usage is quite simple:

# This will download the file at the URL to your current working dir
wget <URL>

For the nf-core pipeline run in Lecture C, you will need the reference genome FASTA file for Culex pipiens, the focal species of the Garrigós et al. (2025) RNA-seq dataset we’ve been working with. The files for that genome can be found at this NCBI FTP webpage :

You can right-click on any of the files there and then click “Copy Link Address” (or similar, depending on your browser). Do that to get the URL to the assembly FASTA (_genomic.fna.gz) file.

NoteAnother download command: curl

Another commonly used download command is curl. The two have similar functionality, so you don’t necessarily need to learn both, but you’re likely to see examples with curl elsewhere, and genAI tools may suggest it to you. One key difference is that by default, curl prints the downloaded contents to the screen instead of saving them to a file: use its -O option to save the file under its original name.

5 File compression

Large data files, like the genome FASTA file you just downloaded, are usually distributed in compressed form to save storage space and download time. A very common compression format is gzip, recognizable by the .gz extension.

Many bioinformatics programs can read gzipped files directly (for example, you’ve never had to decompress your FASTQ files) and to view gzipped files, you’ve been using zcat instead of cat. But some programs can’t read gzipped files, so sometimes you do need to decompress (“unzip”) a file.

5.1 Decompressing files with gunzip

To decompress a gzipped file, use the gunzip command:

gunzip sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna.gz
ls -lh sandbox/GCF*
-rw-rw----+ 1 jelmer PAS0471 547M Dec 22  2022 sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna

Files are decompressed in place, i.e. replaced by an uncompressed file with the same name minus the .gz.

NoteDecompressing multiple files at once (Click to expand)

You can pass gunzip multiple files at once, for example with a wildcard. Say you have a dir data with three gzipped files:

ls data
sampleA.fastq.gz  sampleB.fastq.gz  sampleC.fastq.gz

The following would decompress all three, with the -v (verbose) option making gunzip report on each file:

gunzip -v data/*.gz
data/sampleA.fastq.gz:   74.1% -- replaced with data/sampleA.fastq
data/sampleB.fastq.gz:   73.8% -- replaced with data/sampleB.fastq
data/sampleC.fastq.gz:   74.3% -- replaced with data/sampleC.fastq

5.2 Compressing files with gzip

Conversely, to compress a file, use gzip, which also works in place:

gzip sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna
ls -lh sandbox/GCF*
-rw-rw----+ 1 jelmer PAS0471 165M Dec 22  2022 sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna.gz

The compressed file is less than a third of the size of the uncompressed one. So, only decompress files when needed, and consider compressing large plain-text files that you don’t use often.

Self-study question: Say you need an uncompressed version of a gzipped file, but also want to keep the gzipped file. How could you do this with commands you already knew before this week?

Use zcat and redirect its output to a new file, e.g.:

zcat sandbox/genome.fna.gz > sandbox/genome.fna

zcat only reads the gzipped file, so that file won’t be changed.

NoteWays to keep the original file with gzip/gunzip (Click to expand)

Because gzip and gunzip replace the input file, you only have one version of the file afterwards. To keep the original, use the -k (keep) option:

gunzip -k sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna.gz
ls sandbox/GCF*
sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna  sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna.gz

You may also see the following method, which additionally lets you choose the name of the output file: the -c option makes gzip/gunzip print the output to standard out, which you can then redirect to a file:

gzip -c sandbox/GCF_016801865.2_TS_CPP_V2_genomic.fna > sandbox/genome_copy.fna.gz

6 Checking dir sizes with du

It’s often useful to know how much space your dirs take up. But as you saw in week 4, the sizes that ls -l shows for dirs don’t correspond to the total size of the dir and its contents. Instead, you can use the du (disk usage) command for this purpose.

  • Get the total size for a single dir with options -s (summarize, i.e. only show the total) and -h (human-readable):

    du -sh ../garrigos/fastq
    941M    ../garrigos/fastq

  • Get the total size of each dir directly inside a dir, plus that of the dir itself, with -d 1 (depth of 1):

    du -h -d 1 ../garrigos
    1.0K    ../garrigos/meta
5.1M    ../garrigos/ref
941M    ../garrigos/fastq
946M    ../garrigos/.git
1.9G    ../garrigos

Note that unlike ls, du includes hidden dirs like .git by default. When you’re looking for what takes up the most space, that’s useful, because hidden dirs can be surprisingly large — as you can see in the output above.

TipWhy is the .git dir about as large as the fastq dir? (Click to expand)

The FASTQ files were committed to the garrigos repo, so Git stores its own copy of each of them in .git. And because FASTQ files are already compressed, Git can’t make these copies any smaller. This is one reason not to commit large data files to a Git repo.

I made an exception for the garrigos repo because it’s a practice dataset: the FASTQ files were subset to keep them fairly small, they will never change (so Git won’t accumulate multiple versions of them), and a single git clone was an easy way to give you all the files at once in week 4.

7 Recap

In this lecture, you have learned about best practices for managing and sharing your data, including why to prefer relative paths and how to organize metadata in spreadsheets (slides), and the following practical applications:

  • File transfer to and from OSC with scp (and what other options exist)
  • Downloading files at the command line with wget
  • Compressing and decompressing files with gzip and gunzip, and checking dir sizes with du
