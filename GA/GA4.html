What you’ll practice

In this graded assignment, you will first do the following without genAI: write a shell script to run the program TrimGalore, run it, and interpret its output. Then, you’ll use Claude Code to review and extend your script, to write a loop that runs it for multiple samples, and to summarize the results.

Part B: A TrimGalore script — without genAI

TrimGalore (Krueger 2026) is a commonly used tool to preprocess the reads in FASTQ files before further analysis. It’s the next step in the RNA-seq analysis workflow we’re gradually applying to the Garrigós et al. (2025) data in this course:

TrimGalore takes FASTQ files as input, and outputs filtered FASTQ files, along the way removing:

  • Any adapter sequences that are present in the reads1
  • Poor-quality bases at the end of the reads
  • Reads that have become very short after the prior two steps

Unlike FastQC, TrimGalore isn’t run on one FASTQ file at a time: when you have paired-end reads, like we do with the Garrigós et al. (2025) data, a single TrimGalore run should include both the R1 (forward read) and R2 (reverse read) file for one sample. This is because R1 and R2 files should remain “synced”: generally, you can’t remove a read from an R1 file without also removing its mate from the R2 file.

NoteMore about TrimGalore and similar programs (Click to expand)

Several largely equivalent tools exist for this kind of FASTQ preprocessing — Trimmomatic and fastp are two other commonly used ones. TrimGalore started out as a “wrapper” around yet another tool called Cutadapt, but since version 2 (which we’re using), it is a standalone program. Two advantages of TrimGalore are:

  • It will auto-detect the adapters that are present in your reads.
  • It can automatically run FastQC on the trimmed sequences.

  1. Get a link from the Seqera Containers website to a container with TrimGalore version 2.3.0 (note: the package is called trim-galore). Then, print TrimGalore’s help info by running trim_galore --help with your container link. Use this help info to find the TrimGalore options to:

    • Tell it that your reads are paired-end2
    • Set the output dir
    • Make it run FastQC on the trimmed FASTQ files

  2. Also use the help info to find the default thresholds for A) the base quality score and B) the read length, and report what they are. (You don’t have to change these thresholds, the defaults work fine for us.)

  3. Write a shell script scripts/trimgalore.sh that runs TrimGalore on the R1 and R2 FASTQ files of one sample:

    • The script should accept three arguments: the R1 FASTQ file, the R2 FASTQ file, and the output dir.
    • Use the three options from question 3.
    • Include “logging statements” with echo, like in the FastQC script from class. (You don’t need to separately print the TrimGalore version, since it is printed automatically when you run the program.)
    WarningStick to using the default setting for the number of cores, for now. (Click to expand)

    Since you’re running the program interactively on your single-core VS Code compute job, you only have 1 core at your disposal. Using 1 core is TrimGalore’s default, so don’t adjust this setting here with TrimGalore’s --cores option. Next week, you’ll learn to submit scripts as batch jobs, which gives you the opportunity to use multiple cores to speed things up.

  4. Run your script for the FASTQ files of sample S63 (in ../garrigos/fastq), with results/trimgalore as the output dir. Then, list the files in the output dir, and briefly describe what each type of output file contains. Once your script works, commit it. (If it failed, try to fix your script, and briefly describe the problem and your fix in the README.)

  5. TrimGalore printed quite a bit of logging output to the screen, while additional information is saved in the *_trimming_report.txt output files. Use this information to answer the following:

    • Which adapter sequence did TrimGalore look for in the reads, and how did it decide on this (you didn’t tell it which adapter to look for)?
    • In each file (R1 and R2), in what percentage of reads were adapters detected?
    • In each file, were more bases removed as a result of quality trimming or adapter trimming?
    • What percentage of read pairs were removed altogether?

  6. TrimGalore also reports on poly-G trimming. Newer Illumina sequencers, such as the NextSeq and NovaSeq, use a “two-color” chemistry in which G bases produce no signal. As a result, when the signal is lost near the end of a read, the sequencer calls a stretch of false Gs, which should be trimmed off. Use TrimGalore’s logging output and the trimming reports to answer the following:

    • Did TrimGalore do poly-G trimming, and did you have to tell it to?
    • What does TrimGalore conclude about the sequencing technology that was used to generate these reads?
    • Was more poly-G trimming done in the R1 or the R2 file? (Optional: any idea why?)

  7. Compare TrimGalore’s FastQC report for the trimmed R1 file with the FastQC report for the raw R1 file of the same sample (the one you copied to results/fastqc).

    • Name at least two differences between the reports. Do things look better now in terms of pass/warn/fail status?
    • Do the short reads with only Ns, which you saw in week 4, appear to have been removed? If so, was that due to the length threshold, or something else?
    • Name something you didn’t expect or are confused about.

4. Default thresholds

The relevant parts of the help output:

  -q, --quality <QUALITY>
        Quality trimming cutoff (Phred score). Bases below this are trimmed from 3' end
        [default: 20]

      --length <LENGTH>
        Minimum required sequence length after trimming. Default: 20 (18 for smallRNA adapter).
        In paired-end mode, both reads must pass; see --retain_unpaired to keep single survivors

  • A) The default base quality score threshold (option -q/--quality) is 20, which corresponds to an estimated 0.01 error rate. TrimGalore will trim bases with a lower quality score than this threshold from the end (3’ end) of the reads — it will not remove or mask low-quality bases elsewhere in the read, such as in the middle.

  • B) The default read length threshold (option --length) is 20 bp: any reads that are shorter than this after adapter and quality trimming will be removed. With paired-end input, the corresponding other read will also be removed, regardless of its length: paired-end FASTQ files always need to contain both the R1 and R2 for each pair.

    "$fastq_r2"

9. Compare the FastQC reports before and after trimming

There are clear differences in, for example:

  • Pass/warn/fail status: “Per base N content” went from warn to pass, and “Overrepresented sequences” from fail to pass. Other modules kept their status, including “Per sequence GC content” (still fail).

14. Claude writes a loop

A correct loop:
