Overview and grading

What you’ll practice

In this graded assignment, you’ll run a multi-step RNA-seq workflow on the Garrigós et al. (2025) data, from raw reads to transcript counts. You’ll organize it like we discussed in week 10: with single-step shell scripts that you submit as Slurm batch jobs, and a Markdown “protocol” with the code to run these scripts in order. Along the way, you’ll quantify gene expression with Salmon, and you’ll summarize the results of all steps in a single MultiQC report.

    scripts/trimgalore.sh
    #!/bin/bash
#SBATCH --account=PAS3493
#SBATCH --cpus-per-task=8
#SBATCH --time=30
#SBATCH --output=slurm-trimgalore-%j.out
#SBATCH --mail-type=FAIL
set -euo pipefail

# Run TrimGalore on the paired-end FASTQ files of one sample
# Usage: sbatch scripts/trimgalore.sh <R1 FASTQ file> <R2 FASTQ file> <output dir>

# Constants
TRIMGALORE_CONTAINER=oras://community.wave.seqera.io/library/trim-galore:2.3.0--a56e49e832976df4

# Copy the placeholder variables
fastq_r1="$1"
fastq_r2="$2"
outdir="$3"

# Initial logging
echo "# Starting script trimgalore.sh"
date
echo "# Input R1 FASTQ file:      $fastq_r1"
echo "# Input R2 FASTQ file:      $fastq_r2"
echo "# Output dir:               $outdir"
echo

# Create the output dir (with a subdir for Slurm logs)
mkdir -p "$outdir"/logs

# Run TrimGalore
apptainer exec "$TRIMGALORE_CONTAINER" trim_galore \
    --cores 8 \
    --paired \
    --fastqc \
    --output_dir "$outdir" \
    "$fastq_r1" \
    "$fastq_r2"

# Build the output file names:
sample_id=$(basename "$fastq_r1" _R1.fastq.gz)
R1_out_init="$outdir"/"$sample_id"_R1_val_1.fq.gz
R2_out_init="$outdir"/"$sample_id"_R2_val_2.fq.gz
R1_out_final="$outdir"/"$sample_id"_R1.fastq.gz
R2_out_final="$outdir"/"$sample_id"_R2.fastq.gz

# Rename the output files:
echo
echo "# Renaming the output files:"
mv -v "$R1_out_init" "$R1_out_final"
mv -v "$R2_out_init" "$R2_out_final"

# Final logging
echo
echo "# TrimGalore version:"
apptainer exec "$TRIMGALORE_CONTAINER" trim_galore --version
echo "# Successfully finished script trimgalore.sh"
date

# Usage: sbatch scripts/salmon_quant.sh <R1 FASTQ file> <R2 FASTQ file> <Salmon index dir> <output dir>

# Constants
SALMON_CONTAINER=oras://community.wave.seqera.io/library/salmon:2.8.0--3c08cbdc1b311e75

# Copy the placeholder variables
R1="$1"
R2="$2"
index_dir="$3"
outdir="$4"

# Infer the "sample ID" - we need this for the output dir specification
sample_id=$(basename "$R1" _R1.fastq.gz)

# Initial logging
echo "# Starting script salmon_quant.sh"
date
echo "# Input R1 FASTQ file:            $R1"
echo "# Input R2 FASTQ file:            $R2"
echo "# Input Salmon index:             $index_dir"
echo "# Output dir:                     $outdir"
echo "# Sample ID (inferred):           $sample_id"
echo

# Create the output dir (with a subdir for Slurm logs)
mkdir -p "$outdir"/logs

# Run Salmon
apptainer exec "$SALMON_CONTAINER" salmon quant \
    --index "$index_dir" \
    --libType A \
    --mates1 "$R1" \
    --mates2 "$R2" \
    --threads 8 \
    --output "$outdir"/"$sample_id"

#? - Note: keeping this command as simple as possible -
#?   if using Salmon in your research, then look into, e.g., the --gcBias and
#?   --seqBias options as well.
#? - Explanation of some of the options used:
#?   --libType A                     => Automatically infer the library type (e.g., strandedness)
#?   --mates1 / --mates2             => The R1 and R2 FASTQ files of a paired-end sample
#?   --output "$outdir"/"$sample_id" => Each sample gets its own output dir

# Final logging
echo
echo "# Used Salmon version:"
apptainer exec "$SALMON_CONTAINER" salmon --version
echo "# Successfully finished script salmon_quant.sh"
date

Part C: Transcript quantification with Salmon

In week 11, the nf-core rnaseq pipeline first aligned the reads to the reference genome with STAR, and then used Salmon to quantify gene expression based on those alignments. Here, you’ll use Salmon on its own: it can also directly map the reads to the reference transcriptome, i.e. to the sequences of all annotated transcripts, and estimate how many reads came from each transcript.

NoteMore about Salmon’s mapping approach (Click to expand)

This approach is often loosely called pseudo-alignment (Salmon’s current method is technically called “selective alignment”), because it doesn’t produce full read alignments. Compared to aligning to the genome, it has the following advantages and disadvantages:

  • Pseudo-alignment is much faster and needs much less memory.
  • It doesn’t need to be “splice-aware” like STAR: since transcript sequences don’t contain introns, reads from mature mRNAs match them without gaps.
  • But you can only quantify known transcripts, i.e. those in the annotation, and you don’t get alignment (BAM) files, which you would need for other purposes, like visualizing alignments or calling variants.

Like with most aligners, Salmon needs an index of the reference sequences. You’ll first create this index, and then use it in the quantification step.

  1. Create the index. Take a look at the salmon_index.sh script, add the code to run it to your protocol, and run it. (Only a single index is needed, so you’ll run this script just once.) When it’s done, report how long it took to create the index, and how large the index dir is.

  2. Quantify the reads. Now, add code to your protocol to run the salmon_quant.sh script, for one sample at a time, to quantify the trimmed reads using the index (note: the third argument is the dir of the index, not a file). Then, run it.

  3. Take a look at Salmon’s main output file, quant.sf, for sample S63, and use the Salmon documentation on its output files to understand what the columns in this file mean, especially NumReads. Then, write a command that prints the 3 rows of its quant.sf file with the highest NumReads values (see the self-study section on sorting by column).

  4. For the most abundant transcript you found in the previous question, find its FASTA header in the reference transcriptome file, and report which gene it belongs to.

    NoteTranscript versus gene counts (Click to expand)

    Salmon has quantified the number of reads that came from each transcript. But for most analyses, such as a differential expression analysis, you’ll want counts per gene, not per transcript. Using a mapping from transcripts to genes, which you can e.g. extract from a GTF file, you can sum the transcript counts for each gene to get gene-level counts.

  5. Salmon reports the mapping rate, i.e. the percentage of reads that it could assign to a transcript, in the file logs/salmon_quant.log within each sample’s output dir. Write a command that prints the mapping rate for all samples at once. Which sample has the lowest mapping rate?

    Click here for a hint

    As for the globbing: so far, you’ve used the * wildcard to match file names within a single dir. But a * can also stand in for a dir name anywhere in a path. For example, the following lists the contents of the logs dirs of all your workflow steps so far:
