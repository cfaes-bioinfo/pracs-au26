Part C: A script to run MultiQC

MultiQC is a very useful program that summarizes per-sample results of FastQC and other bioinformatics programs into a single multi-sample report. This allows you to easily compare results across multiple samples.

MultiQC takes a path to a directory as input, and it will recursively search that directory for files that it can summarize, such as FastQC results. It will then write its summary report to an output directory.

  1. MultiQC isn’t available as an OSC module (optional: verify this). Get a link from the Seqera Containers website to a container with the most recent version of MultiQC (bioconda::multiqc is the correct hit).

  2. Print MultiQC’s help info by running multiqc --help with your container link. Use the help info to figure out how to run MultiQC with results/fastqc as its input dir and results/multiqc as its output dir, and write down that command in your README.md (don’t run it yet).

  3. Write a script, scripts/multiqc.sh, to run MultiQC using the command you wrote above. That is, the script will have the input and output paths “hard-coded” in it. Optional: add some logging statements to the script with echo, like we did in class for the fastqc.sh script.

  4. Run your script to summarize the FastQC results with MultiQC. MultiQC will print logging information to the screen — how many FastQC reports does it say it found, and does that match what you expected? Commit your scripts/multiqc.sh script now that you know it works.

  5. Change your scripts/multiqc.sh script so that it accepts two arguments, the input dir and the output dir, and uses these when running MultiQC. Then, rerun your script, passing the same input and output dirs as before (results/fastqc and results/multiqc) as arguments. #!/bin/bash

13. Differences between the two MultiQC runs

In the second run, MultiQC printed the following line:

Existing reports found, adding suffix to filenames. Use '--force' to overwrite.

So, rather than overwriting the output files from the first run, it added a _1 suffix to the names of the new output files. The output dir now contains both reports:

ls results/multiqc
multiqc_data  multiqc_data_1  multiqc_report_1.html  multiqc_report.html
  • These differences are caused by using the same output dir twice, combined with MultiQC not overwriting existing reports by default. The --force (-f) option would make it overwrite them.

Part D: Pandoc to render Markdown

14. The structure of the Pandoc command

In pandoc -o README.pdf README.md:

  • pandoc is the command (program).
  • -o README.pdf is an option that takes a value, the output file (-o is short for --output).
  • README.md is an argument, the input file.

Pandoc infers the output format from the extension of the output file name (.pdf), and similarly, the input format from the extension of the input file name (.md). You can also set the formats explicitly with the --to (-t) and --from (-f) options.

16. Should the rendered files be committed?
  • Generally, no: the PDF and HTML files are output that you can regenerate from README.md at any time, just like the files in results. Committing them would add redundant files to your repo, and each time you change your README, you’d also need to rerender and commit these files to keep them in sync. Also, Git can’t show meaningful differences between versions of a binary file like a PDF.
  • You could add these files to your .gitignore, e.g. with the lines README.pdf and README.html.
  • That said, a “yes” with a reasonable justification is also fine — for example, to make the PDF directly available to collaborators who don’t use Markdown.
