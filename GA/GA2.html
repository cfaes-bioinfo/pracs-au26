Part B: Exploring the GTF file with Unix data tools

  1. Create a dir data and a dir results inside your working dir. Then, copy the genome annotation GTF file annot.gtf.gz that is in your copy of the Garrigós et al. (2025) data into your data dir, keeping the same file name.

  2. Check the file size of annot.gtf.gz.

  3. Decompress the GTF file with the gunzip command below, and check the size of the resulting annot.gtf file. Roughly how many times larger is the uncompressed file than the compressed file?

    gunzip data/annot.gtf.gz

  4. A GTF file starts with a few “header lines” (metadata), followed by its main/table section, in which each line describes one “genomic feature” (a gene, exon, etc.). Use a command to count the total number of lines in annot.gtf.

  5. Now, look at the GTF file contents to count the number of header lines by eye, like in last week’s exercises. How many lines does that leave for the table section?

  6. Now, count the number of lines in the table section in a more automated way: based on what you know about what GTF header lines look like, combine grep -v with another option or command to count the number of lines that are not header lines. What count do you get?

    Click here for some hints.

    • The -v option inverts grep’s behavior, so that it prints all lines that do not match the pattern (see the “Additional useful grep options” box in the section on grep). Use this option with a search pattern that matches the header lines.

    • Then, to get a line count, add another grep option to your command, or pipe the output of the grep command into wc -l.

    • You should encounter a minor difference in the number of lines counted in this question vs. the previous one. If you want to, you can try to figure out why that is as part of the bonus question at the end.

  7. How many distinct “sequences” (chromosomes/scaffolds/contigs) are represented in the annotation file? Store a list of these distinct sequences in a file results/scaffolds.txt.

    Click here for some context and a hint.

    • Context: The number of sequences gives a rough idea of the quality of the genome assembly, because a high-quality assembly will have only a few sequences, ideally one per chromosome. (Note, though, that any sequences in the genome assembly FASTA file that don’t have any annotated features would not be represented in the GTF file.)

    • Hint: In this and the following GTF questions, you’ll only want to consider the table part of the file, so start your commands with the same (or a similar) grep -v command as above.

  8. Print a “frequency table” of feature types in the annotation: this should have a count of the number of times each feature type occurs.

    Click here for some context and a hint.
    • Context: A frequency table of feature types will for example show how many genes have been annotated in this genome — that’s quite useful!
    • Hint: Feature types are in the 3rd column of the table part of the GTF file.

  9. A labmate wants to know how many genes have been annotated in this genome, and runs the command below:

    grep -c "gene" data/annot.gtf

    Before running it, predict which of the following statements is true:

    1. This gives the correct number of genes.
    2. This overcounts the number of genes, because the word “gene” also occurs in lines for other feature types.
    3. This undercounts the number of genes, because grep only matches whole words.
    4. This command gives an error, because the file is tab-delimited.

    Then, run the command and compare its output with the number of genes in your frequency table from question 11. Was your prediction correct, and what does this comparison tell you? (No points will be subtracted if you didn’t predict correctly.)

Part B: Exploring the GTF file with Unix data tools

4. Create data and results dirs and copy the GTF file. 
mkdir data results
cp ../garrigos/ref/annot.gtf.gz data/

Neither command prints any output. Using the absolute path to the GTF file (/fs/ess/PAS3493/people/<user>/garrigos/ref/annot.gtf.gz) is fine too.

5. Check the file size of annot.gtf.gz. 
ls -lh data/annot.gtf.gz
-rw-r--r-- 1 <user> PAS3493 5.1M Sep 25 14:02 data/annot.gtf.gz

The compressed file is 5.1 MB.

6. Decompress the GTF file and compare file sizes. 
gunzip data/annot.gtf.gz
ls -lh data/annot.gtf
-rw-r--r-- 1 <user> PAS3493 123M Sep 25 14:02 data/annot.gtf

The uncompressed file is 123 MB, which is roughly 24 times larger than the compressed file (123 / 5.1 ≈ 24). That’s a big difference, and the reason that large genomic files are typically stored in compressed form.

7. Count the total number of lines in annot.gtf. 
wc -l data/annot.gtf
408402 data/annot.gtf

The file has 408,402 lines in total.

8. Count the header lines by eye. 
head -n 5 data/annot.gtf
#gtf-version 2.2
#!genome-build TS_CPP_V2
#!genome-build-accession NCBI_Assembly:GCF_016801865.2
#!annotation-source NCBI RefSeq GCF_016801865.2-RS_2022_12
NC_068937.1     Gnomon  gene    2046    110808  .       +       .       gene_id "LOC120427725"; transcript_id ""; db_xref "GeneID:120427725"; description "homeotic protein deformed"; gbkey "Gene"; gene "LOC120427725"; gene_biotype "protein_coding";
  • There are 4 header lines, all starting with a #.
  • That leaves 408,402 - 4 = 408,398 lines for the table section.
  • Other commands to view the file, like less -S data/annot.gtf, are fine too.
9. Count the number of lines in the table section with grep -v. 
grep -v "#" data/annot.gtf | wc -l
408397
  • This gives 408,397 lines: one less than in the previous question — see bonus question 21 for the explanation.
  • Instead of piping to wc -l, you can use grep’s -c option: grep -vc "#" data/annot.gtf.
  • The quotes around # are needed: without them, the shell interprets everything from the # onwards as a comment, so grep wouldn’t get a search pattern at all.
10. Count the distinct sequences and save them to results/scaffolds.txt.
  • First, exclude the header lines with grep -v.
  • Then, select the first column, which contains the sequence names, with cut -f 1.
  • To only keep distinct sequences, use sort | uniq, and write the output to a file.
  • Finally, count the number of lines in the resulting file with wc -l.
grep -v "#" data/annot.gtf | cut -f 1 | sort | uniq > results/scaffolds.txt
wc -l results/scaffolds.txt
167 results/scaffolds.txt

  • There are 167 distinct sequences.

  • If you forgot grep -v "#", you got 172: the # lines don’t contain any tabs, so cut prints them in full, and each of these 5 lines is counted as an additional “sequence”.

  • The file results/scaffolds.txt should start like this:

    head -n 4 results/scaffolds.txt
    NC_015079.1
NC_068937.1
NC_068938.1
NC_068939.1
11. Print a frequency table of feature types.

The feature types are in the 3rd column:

grep -v "#" data/annot.gtf | cut -f 3 | sort | uniq -c
 141444 CDS
 166177 exon
  19673 gene
  25864 start_codon
  25892 stop_codon
  29347 transcript
  • So, for example, 19,673 genes have been annotated in this genome.
  • Adding | sort -nr to sort the table by count is a nice touch.
12. Predict, then run grep -c "gene". 
grep -c "gene" data/annot.gtf
408397
  • The correct answer is b): this overcounts the number of genes. The command returns 408,397, which is far more than the 19,673 genes in the frequency table from question 11.
  • That’s because nearly every line in the GTF file contains “gene” in its 9th (attributes) column, in gene_id "..." and gene "LOC...". In fact, 408,397 is exactly the number of table lines from question 9: every line in the table section matches.
  • The lesson: grep matches a pattern anywhere in a line, so to count genes, you need to check the feature type column specifically, as you did in question 11.
  • Regarding the other answers: grep does not only match whole words (unless you use its -w option), and it doesn’t care whether a file is tab-delimited.

18. How many reads does the FASTQ file contain? 
zcat data/S63_R1.fastq.gz | wc -l
2000000
  • Each read takes up 4 lines in a FASTQ file, so the file contains 2,000,000 / 4 = 500,000 reads.
  • Running wc -l data/S63_R1.fastq.gz directly on the compressed file returns 101,139, which is meaningless: you need to count the lines of the decompressed output.
19. How many reads contain at least 10 consecutive Ns? 
zcat data/S63_R1.fastq.gz | grep -c "NNNNNNNNNN"
32612
  • 32,612 reads contain at least 10 consecutive Ns.
  • A read with more than 10 consecutive Ns also matches, and is still counted only once, since grep -c counts matching lines.

Bonus

21. Why do the counts from questions 8 and 9 differ?

Use grep’s -n option to print line numbers along with each matching line:

grep -n "#" data/annot.gtf
1:#gtf-version 2.2
2:#!genome-build TS_CPP_V2
3:#!genome-build-accession NCBI_Assembly:GCF_016801865.2
4:#!annotation-source NCBI RefSeq GCF_016801865.2-RS_2022_12
408402:###
  • Besides the 4 header lines, the last line of the file, ###, also contains a #. This line seems to function as an end-of-file marker.
  • It is not a header line, so you didn’t count it as one in question 8, but grep -v "#" did exclude it in question 9: 408,402 - 5 = 408,397.
  • You could also have found this line by looking at the end of the file with tail data/annot.gtf.
