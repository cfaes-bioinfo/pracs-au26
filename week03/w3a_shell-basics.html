1 Introduction

1.1 Context & overview

Throughout the rest of this course, you’ll be using the Unix shell regularly. This is the first of several lectures completely focused on learning to work in it. We’ll start with a conceptual introduction, and then you’ll take your first steps in the Unix shell!

1.2 Learning goals

In this lecture, you’ll learn:

  • What the Unix shell is and what you can do with it
  • Why it can be beneficial to use a command-line interface in general, and the Unix shell specifically
  • How you execute shell commands, and how they are structured
  • How to get help on a command’s options and arguments
  • What environment variables are and how to print their values
  • How to navigate around a computer with shell commands
  • Keyboard shortcuts that make working in the shell much more efficient

2 The Unix shell

2.1 Some terminology and concepts

Unix-based (or Unix-like) operating systems include macOS and Linux but not Windows. For scientific computing, Unix-based operating systems are generally preferable. Supercomputers like those of OSC, and most servers throughout the world, run on Linux specifically.

NoteHave Windows?

Don’t be alarmed if you have a Windows laptop/desktop. Certainly for the purposes of this course, and in principle for your other research, your computer can run on any operating system. That’s because you can connect to OSC and do your work there.

This session introduces the “Unix shell”. Terminology around the Unix shell can be confusing, and some terms are used interchangeably. Let’s run through these terms, going from more general ones to more specific ones:

Term Explanation
Command Line /
Command Line Interface (CLI)		 A user interface where you type commands rather than pointing-and-clicking like in a Graphical User Interface (GUI). This “interface” can be anything from a specific bioinformatics program to a computer’s operating system.
Shell A more specific and technical term for a command line interface to a computer as a whole.
Unix shell The type of shell found on Unix-based (Linux + Mac) computers.
Bash A specific Unix shell language (the most common one, and the one we’ll use).

Or, shown in another way — each term is a subset of the one around it:

Command line (CLI)

Shell

Unix shell

Bash

Also related is the word terminal: the program/app/window in which the shell is run.

While the above terms are not synonyms, they are often used interchangeably in practice.

2.2 Why use the Unix shell?

The Unix shell can be used for a wide variety of tasks, from “file browser” functionality to running specialized software.

The Unix shell has been around for a long time and may seem a bit archaic. But astonishingly, a system largely built decades ago in an era with very different computers and datasets has stood the test of time, and the ability to use it is a crucial skill in computational biology.

Using the Unix shell rather than programs with GUIs has some of the general advantages of using code we’ve discussed:

  • Automation, fewer errors, and reproducibility
    The shell allows you to repeat and automate tasks easily and with fewer errors, and it’s straightforward to keep a detailed record of what you have done.

There are also specific reasons to use the Unix shell as opposed to (other) coding languages like R and Python:

  • Software needs
    Many programs used for omics data analysis have a CLI and are most easily run from the Unix shell.
  • Viewing and processing large files
    Shell commands are excellent at viewing and processing very large, plain-text files, which are common in omics research.
  • Efficiency and convenience
    Built-in shell tools are often faster in terms of both coding and running time, especially for simpler tasks. And when doing remote computing, the Unix shell is both your point of entry and a universal interface.

3.3 The shell’s prompt

Inside your terminal, the “prompt” indicates that the shell is ready for a command. Exactly what is shown varies across shells and can be customized, but our prompts at OSC should show something like this:

[jelmer@p0362 jelmer]$

This represents the following pieces of information:

The working dir is the directory you are currently located in. For brevity, the prompt only shows the name of the directory you are directly located in (e.g. jelmer) rather than the entire path (e.g. /fs/ess/PAS3493/people/jelmer).

You type your commands after the dollar sign $, and then press Enter to execute the command. When the command has finished executing, you’ll “get your prompt back”, and can execute a new command.

If you see a ~ as the working-dir-part of your prompt, you are instead in your Home directory in /users/ and you will need to go to /fs/ess/PAS3493/people/<user> instead.

While you could navigate there with a simple shell command, you should use the “Open Folder” functionality in VS Code instead. This moves the entire program (and not just the terminal) to the correct dir.

To do so: click File > Open Folder in VS Code and then type/select /fs/ess/PAS3493/people/<user>, replacing <user> with your user name. When you then open a Terminal again, the correct dir should be displayed.

3.4 A few simple commands

The Unix shell comes with hundreds of commands: small programs that perform specific actions2. Let’s start with a few simple commands:

  • The date command prints the current date and time:

    date
    Wed Sep  9 13:58:19 EDT 2026

  • The pwd (Print Working Directory) command prints the path to the directory you are currently located in:

    pwd
    /fs/ess/PAS3493/people/jelmer

  • The echo command simply prints the text you provide it with, typically between double quotes “…”3.

    echo "Welcome to PLNTPTH 5006"
    Welcome to PLNTPTH 5006

All these commands provided us with some output. That output was printed to screen, which is the default behavior for nearly every shell command.

4 Options, arguments, and help

4.1 The cal command — and options & arguments

The cal command is another example of a command that simply prints some information to the screen, in this case a calendar. It’s not a particularly useful command in this day and age 🙃, but we’ll use it as a low-stakes example to learn about command options and arguments.

Just running cal will print a calendar for the current month:

Tip“Comments” in code with #

Any text that comes after a # is considered a comment instead of code! Comments are not executed but are ignored by the shell:

# This entire line is a comment - you can run it and nothing will happen
cal # If you run this line, 'cal' will be executed, but everything after the '#' is ignored

Options summary

Options are specified with a dash - (or two dashes --, as you’ll see later). The examples so far have involved the kind of option that is also called a flag, which changes functionality in an ON/OFF way, such as:

  • Turning Julian (day-of-year) date numbering on with -j
  • Turning a 3-month display on with -3

We’ll see more complex types of options later. Generally speaking, options change the behavior of a command.

  • Usually tell the command what to operate on, instead of changing how to operate
  • Are not preceded by - and a letter (or -- and a keyword)
  • Go after options, if the two are combined4.

4.2 Getting help

Many shell commands have a -h (or --help) option for help, which usually gives a concise summary of the command’s syntax, such as its available options and arguments:

cal -h
Usage:
 cal [options] [[[day] month] year]
 cal [options] <timestamp|monthname>

Display a calendar, or some part of it.
Without any arguments, display the current month.

Options:
 -1, --one             show only a single month (default)
 -3, --three           show three months spanning the date
 -n, --months <num>    show num months starting with date's month
 -S, --span            span the date when displaying multiple months
 -s, --sunday          Sunday as first day of week
 -m, --monday          Monday as first day of week
 -j, --julian          use day-of-year for all calendars
     --reform <val>    Gregorian reform date (1752|gregorian|iso|julian)
     --iso             alias for --reform=iso
 -y, --year            show the whole year
 -Y, --twelve          show the next twelve months
 -w, --week[=<num>]    show US or ISO-8601 week numbers
 -v, --vertical        show day vertically instead of line
     --color[=<when>]  colorize messages (auto, always or never)
                         colors are enabled by default

 -h, --help            display this help
 -V, --version         display version

For more details see cal(1).

In this case, we learn that most options to cal can be referred to in one of two ways:

  • A short-form notation: a single dash followed by a single character (e.g. -s)
  • A long-form notation: two dashes followed by a keyword (e.g. --sunday)
NoteAnother way to see documentation: the man command (Click to expand)

An alternative way of getting help for shell commands is with the man command:

man cal

This manual page often includes a lot more detail than the --help output, and it is opened inside a “pager” rather than printed to screen: type q to exit the pager that man launches.

(The last line of the output of cal -h — “For more details see cal(1)” — referred to this man page.)

5 Environment variables

You may be familiar with the concept of variables from previous experience with R or another language. Either way, variables can hold values and other pieces of data, and they are essential in coding.

While you can create variables yourself, and will learn how to do so later in this course, we’ll now focus on environment variables. These are pre-existing variables that were automatically created by the system when you logged in. Two examples are:

  • $HOME, which contains the path to your Home directory
  • $USER, which contains your user name

Note that in the Unix shell, variables are always referenced using a leading $. This helps you recognize them as variables.

If you want to print the value of a variable, you can’t just type its name: you need to precede it with a command like echo:

echo $HOME
/users/PAS0471/jelmer
echo $USER
jelmer

Code-formatted text between < and > (such as <user> above) represents something that will differ from user to user, or between contexts. For example, <user> above should be read as a placeholder for your actual username, and would be replaced by that username, e.g. by jelmer (not by <jelmer>).

6 Navigation

6.1 cd and command “actions”

All commands so far “merely” provided some information, which was printed to the screen. But many commands instead perform some other kind of action.

For example, the command cd (Change Directory) will change your working directory. First, check again where you are:

pwd
/fs/ess/PAS3493/people/jelmer

Now, use cd to navigate to another directory by specifying the path to that dir as an argument:

cd /fs/ess/PAS3493
# Double-check that you were moved:
pwd
/fs/ess/PAS3493

In summary:

  • Like cal, cd accepts an argument. Unlike with cal, this argument takes the form of a path that the command should operate on (which is very typical among shell commands).

  • cd gives no output when it successfully changes the working directory. This is very common behavior for shell commands that perform operations: when they succeed, they are silent.

Let’s also see what happens when cd does not succeed — it gives an error:

cd /fs/ess/pas3493
bash: cd: /fs/ess/pas3493: No such file or directory
What went wrong here? And what does that tell you? (Click to see the answer.)

We spelled pas in lowercase letters, while the actual dir is spelled PAS3493 in uppercase letters.

Given that this resulted in an error, it appears that the shell is case-sensitive. That is, it treats uppercase and lowercase letters as different characters.

6.2 Absolute versus relative paths

Any path, i.e. the location of any file or dir, can be specified in two ways:

As an absolute path As a relative path
Meaning Starts from the computer’s root dir Starts from your working dir
Recognized by A leading /   5 No leading /
Examples – /fs/ess/PAS3493
– /users/PAS0471		 – week02/exercises
– data/meta/metadata.tsv
Analogy GPS coordinates for a geographical location: valid regardless of where you are. Directions along the lines of “take the second left”: validity depends on your current location.

6.3 Path shortcuts

A number of “shortcuts” exist for paths:

Symbol/shortcut Represents
~ (a tilde) Your Home directory
. (a single period) The current working directory (we’ll see why this is useful later)
.. (two periods) The directory “one level up” from your working dir, i.e. towards the computer’s root dir

Some examples of ..:

  • Use .. to go up one level in the dir hierarchy:

    # Start by reminding yourself of where you are:
pwd
    /fs/ess/PAS3493
    # Move one level up:
cd ..

# Check where you are now:
pwd
    /fs/ess

  • You can “continue” a path like usual after .., e.g.:

    cd ../scratch/PAS3493

pwd
    /fs/scratch/PAS3493

  • Therefore, you can also move up multiple levels at once, e.g.:

    # Move up two levels
cd ../..

pwd
    /fs
TipThese path shortcuts work with many commands

., .., and ~ are general shell shortcuts that work with any command that accepts a path/file name, and not just with cd. We’ll see examples of this next week.

7 Keyboard shortcuts

Keyboard shortcuts help you work much more efficiently in the shell. Here are some of the most useful ones:

  • Command history — ↑ / ↓ arrow keys to cycle through your command history.

  • Tab completion — The shell will auto-complete partial commands or file paths when you press Tab.

  • Cancel/stop/abort — If your prompt is “missing”, one of two things is going on:

    • The shell is still busy executing your command, or
    • You typed an incomplete command.

    Either way: press Ctrl+C to abort/cancel, and you will get your prompt back. In some cases, you need to press it multiple times to get your prompt back.

In the shell, whenever you type something and press Tab, the shell will try to autocomplete what you typed based on the available commands and on the files/dirs in the dir you are typing a path into (which is your working dir if you haven’t typed any dir yet). Why did we get an error at the last step?

  1. The directory PAS3493 doesn’t exist.
  2. We don’t have permission to access that directory.
  3. A path by itself isn’t a command.
  4. Tab completion inserted the wrong character into the path.
  Click to see the answer.

The correct answer is C.

Basically, everything you type in the shell should start with a command. Just typing a path will not make the shell print some info about, or the contents of, this dir or file. Instead, since a path is not a command, you will get an error.

Let’s continue and actually navigate to the dir we just autocompleted with Tab completion:

Type this Expected response
↑ (Up arrow) You get the path back at the prompt!
Ctrl+A Cursor moves to the start of the line.
Prepend cd (to cd /fs/scratch/PAS3493/) => Enter You are now in the PAS3493 dir.

Your cursor can be anywhere in a line (not just at the end) when you press Enter to execute a command!

Bonus exercise: canceling

To simulate a long-running command that you may want to abort, we’ll use the sleep command, which makes the computer wait for a specified amount of time before it gives your prompt back.

Run the below command and instead of waiting for the full 60 seconds, press Ctrl+C to get your prompt back sooner!

sleep 60s

As another example of a situation where you might have to use Ctrl+C, simply type an opening parenthesis ( and press Enter:

(

When you do this, nothing is executed and you don’t get your prompt back: instead, you should see a > on the next line. This is the shell wanting you to “complete” your command. Why would that be?

  Click to see the answer.

This is an incomplete command by definition: any opening parenthesis should have a matching closing parenthesis.

This is true even though () by itself is still not a valid command.

Again, press Ctrl+C to get your regular prompt back.

7.2 Self-study: Table with useful keyboard shortcuts

Even on Macs, you should use Ctrl rather than switching it out for Cmd as you may be used to doing (though in some cases, like copy/paste, both keys work).

Shortcut Function
Tab Tab completion
↑ / ↓ Cycle through previously issued commands
Ctrl+C Copy selected text (only when text is selected — see the Cancel row below)
Ctrl+V Paste text from clipboard
Ctrl+A / Ctrl+E Move cursor to beginning (A) / end (E) of line
Ctrl+U / Ctrl+K Cut from cursor to beginning (U) / end (K) of line
Ctrl+W Cut word before cursor
Ctrl+Y Paste (“yank”) text that was cut with one of the shortcuts above
Alt+. (Windows)
Esc+. (Mac)		 Paste last argument of previous command (very useful!)
Ctrl+R Search your command history: press Ctrl+R again to cycle through matches, Enter to put command in prompt.
Ctrl+C Cancel (or kill/stop/abort) currently active command (when no text is selected)
Ctrl+D Exit (a program or the shell, depending on the context; same as exit command)
Ctrl+L Clear the screen (same as clear command)
