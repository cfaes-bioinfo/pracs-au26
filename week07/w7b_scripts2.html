1 Introduction

1.1 Learning goals

In the previous session, you wrote a shell script to run FastQC for a single FASTQ file. Here, we will focus on running that script many times with loops. Specifically, you will learn:

  • How for loops work
  • How to use a for loop to loop over files and run a shell script many times
  • How to keep a record of your analysis steps in a Markdown file
  • Self-study: How to use parameter expansion to search-and-replace text in variables
  • Self-study: How to loop over samples (e.g., pairs of FASTQ files) rather than individual files

1.2 The big picture

The strategy you’ve learned so far, and that we will stick to, is writing scripts that run a single program a single time. We do this even though you commonly need to run a CLI tool many times, e.g. separately for each file or sample. That’s because at OSC and other HPC systems, you can save a lot of time by submitting a separate batch job for each file or sample, since these jobs can all run simultaneously1. To accommodate this, you will:

  • Make your scripts flexible by passing arguments to them (as seen in the previous session)
  • Loop over files/samples outside of the script, and run/submit the script many times (as you’ll see today)

As a result, you’ll also type important code outside of your scripts, and that code orchestrates your workflow. You will store that code in Markdown files, which then provide a record of what you did.

3 For loops

Loops are used to repeat operations. Here, we’ll cover the most common type of loop, the for loop3, which:

  1. Iterates over (i.e., goes through, one by one) a pre-defined collection, such as a list of files.
  2. Uses one element of the collection in each iteration (or “round”) of the loop, allowing you to perform one or more actions for that element.

3.1 A non-coding example

In a way, you’re likely to already think in for loops regularly in your daily life. Say you have a rack with three tubes, and your protocol says:

For each tube in the rack: add 10 µL of buffer to the tube, vortex it, and spin it down.

Here’s what that instruction consists of:

  • A collection of items to go through: the tubes in the rack.
  • A set of actions that are repeated for every item: add buffer, vortex, spin down.
  • A placeholder that stands in for “the item I’m currently working on”: “the tube” or “it”. In the first round, “the tube” means tube 1; in the second round, tube 2; and so on.

You’d go through the tubes one at a time, doing all three actions for a tube before moving on to the next one. And you’re done when you run out of tubes: with three tubes, you’d do this three times. If we wrote that protocol step in for loop syntax, it would look like this (this is not real code!):

for tube in tube1 tube2 tube3; do
    add 10 µL buffer to $tube
    vortex $tube
    spin down $tube
done

In shell code, a for loop has the same three components:

  • The collection comes after in: here, tube1 tube2 tube3.
  • The actions go between do and done, in indented lines so it’s clear what is being repeated.
  • The placeholder is a variable, whose name you choose and put after for: here, tube. Inside the loop, you refer to it with $tube, and in each round of the loop, it contains a different item from the collection.

3.2 A first shell loop

Let’s type out the example below in your loops-practice.md and then run it in the terminal. Here, the collection is a short list of three fruits, and the only action is to print the current fruit.

3.3 Multiple actions per iteration

Just like in the tube example, you can perform multiple actions in each round of the loop: every line between do and done is run for every item.

For the next example, we will count the number of characters in each fruit’s name. Here’s how to do that for a single word, where we add the -n option to echo to prevent it from adding a newline (which would otherwise be counted as a character too), and use the -c option of wc to count the number of characters rather than lines:

echo -n "apple" | wc -c
5

Below, for each fruit, we print its name and then count the number of characters in its name:

loops-practice.md (excerpt)
for fruit in apple banana plum; do
    echo "Fruit: $fruit"
    echo "Number of characters:"
    echo -n "$fruit" | wc -c
    echo
done
Fruit: apple
Number of characters:
5

Fruit: banana
Number of characters:
6

Fruit: plum
Number of characters:
4

Notice that all four lines ran for apple before any of them ran for banana: the loop completes all actions for one item before moving on to the next item.

3.4 Loop recap so far

To recap some key things you should understand about for loops:

  • In each iteration of the loop, one element in the collection is being assigned to the variable specified after for.
  • The loop will run exactly as many times as there are items in the collection.
  • The indented lines’ code is being repeated: all lines are run for one item before the loop moves on to the next4.
  • The variable name is up to you. Like with other variables, try to choose a name that is descriptive.
  • Like with other variables, use a $ when you reference (echo "$fruit") but not when you assign (for fruit).
NoteMore about the syntax of for loops (Click to expand)

On the first and last, unindented lines, for loops contain the following mandatory keywords:

Keyword Purpose
for After for, we set the variable name (an arbitrary name; above we used fruit)
in After in, we specify the collection (list of items) we are looping over
do After do, we have one or more lines specifying what to do with each item
done Tells the shell we are done with the loop
TipWhy is there “; do” in a for loop? (Click to expand)

You may find the ; do at the end of the first line of the for loop to be odd. What is that all about?

First, let’s see what a semicolon does in the first place. It’s a way to enter multiple commands on a single line — for example, the line below would first run ls and then echo "Hello":

ls; echo "Hello"

(So, ; can be thought of as a counterpart to \, which allows you to spread a single command across multiple lines: with a ;, you can have multiple commands on a single line.)

Alternatively, you could write for loops like so:

for fruit in apple banana plum
do
    echo "Fruit: $fruit"
done

Some people prefer that variant. You can do it either way, but we will continue to demonstrate the ; do variant, which is more symmetric, and saves a line of code.

3.5 Combining loops and globbing

In an omics data analysis, you will often have many files that need to be processed in the same way. For example, we wrote a fastqc.sh script that runs FastQC for a single FASTQ file, and we want to run that script for all FASTQ files in a directory. We can loop over file names just like we looped over fruits above:

loops-practice.md (excerpt)
for fastq_file in ../garrigos/fastq/S63_R1.fastq.gz ../garrigos/fastq/S63_R2.fastq.gz; do
    echo "Now processing file: $fastq_file"
done
Now processing file: ../garrigos/fastq/S63_R1.fastq.gz
Now processing file: ../garrigos/fastq/S63_R2.fastq.gz

However, typing out all file names is tedious and error-prone. Instead, we can use globbing to automatically generate a list of file names, and then loop over that list, all in one line of code:

loops-practice.md (excerpt)
for fastq_file in ../garrigos/fastq/*fastq.gz; do
    echo "Running an analysis on $fastq_file"
    # [This is where you would put additional commands to process each FASTQ file]
done
Running an analysis on ../garrigos/fastq/S63_R1.fastq.gz
Running an analysis on ../garrigos/fastq/S63_R2.fastq.gz
Running an analysis on ../garrigos/fastq/S64_R1.fastq.gz
Running an analysis on ../garrigos/fastq/S64_R2.fastq.gz
# [...output truncated...]

The shell expands the glob into a list of matching file names before the loop starts (recall from week 4 that expansion is done by the shell itself), so to the loop, this is no different from the typed-out list of file names above.

The glob only matches the two FASTQ files, so the loop runs twice:

I have found file sandbox/S1_R1.fastq.gz
I have found file sandbox/S1_R2.fastq.gz
for file in sandbox/f*; do
    echo "$f"
done
Click for the solution

Look closely: the loop variable is file, but the echo line uses $f — a variable that was never assigned. Because we’re at the interactive prompt rather than in a script with set -u, the shell doesn’t complain about the unset variable, instead treating it as an empty string.

So the loop prints one empty line for each matching file: here, that is just file1.txt. This is exactly the kind of silent failure that set -u protects you from: in a script with strict Bash settings, this typo would cause an immediate error instead.

for file in sandbox/*.bam; do
    echo "I have found file $file"
done
Click for the solution

You might expect no output at all, since no files match the pattern. But when a glob pattern doesn’t match any files, the shell leaves the pattern as is, so the loop runs once, with the literal string sandbox/*.bam:

I have found file sandbox/*.bam

So if you make a typo in a glob pattern in a loop that runs a script, the script will be run once for a non-existent “file”. This is one more reason to print input file names in your scripts’ logging output!

5 Self-study: Looping over samples

FastQC is run separately for each FASTQ file, but many tools that process paired-end data need the R1 and R2 files of a sample together. Such tools should be run once per sample, i.e. once per pair of FASTQ files.

How can you loop over pairs of FASTQ files? There are two main ways:

  • Create a list of sample IDs, loop over these IDs, and find the pair of FASTQ files with matching names.
  • Loop over the R1 files only and then deduce the name of the corresponding R2 file inside the loop. This works because R1 and R2 file names are identical except for the read-direction identifier (typically _R1/_R2).

We will use the second method. To deduce the R2 file name, you’ll first need to learn about parameter expansion.

Type and run the code in this self-study section from your loops-practice.md file.

5.1 Parameter expansion

“Parameter expansion” (“parameter” is another word for variable) is the shell’s term for retrieving a variable’s value, as in $fastq. Some special forms of parameter expansion modify the value as it is retrieved — for example, to search-and-replace text:

  • Start by assigning a short DNA sequence to a variable:

    dna_seq="AAGTTCAT"
echo "$dna_seq"
    AAGTTCAT

  • Now, use parameter expansion to replace all Ts with Us:

    echo "${dna_seq//T/U}"
    AAGUUCAU

  • You can also assign the result of the parameter expansion back to a variable:

    rna_seq="${dna_seq//T/U}"
echo "$rna_seq"
    AAGUUCAU

So, the syntax for this type of parameter expansion is ${var_name//<search>/<replace>} — let’s deconstruct that:

  1. You reference the variable using the “full notation” with braces: here, ${dna_seq}.
  2. You add two forward slashes after the variable name, and then the search pattern: here, //T.
  3. After another forward slash, enter the replacement: here, /U.
NoteReplace all matches or just the first? (Click to expand)

If you only want to replace the first match, use a single forward slash after the variable name: ${var_name/<search>/<replace>}. Compare:

echo "${dna_seq/T/U}"
AAGUTCAT

Next, a labmate suggests the shorter fastq_R2="${fastq_R1/1/2}". Does that give the correct result for this file? Would it still work if the sample were called S61 instead of S63?

It works for S63, since the first 1 in the path happens to be the one in R1. But for ../garrigos/fastq/S61_R1.fastq.gz, the 1 in the sample ID would be replaced instead, giving ../garrigos/fastq/S62_R1.fastq.gz — the R1 file of a different sample! So, make your search pattern as specific as possible, like _R1.

5.2 A per-sample loop

Using parameter expansion, you can create a loop that iterates over R1 FASTQ files only, and then deduces the corresponding R2 file name. Here is a loop that runs once per sample, and prints the two file names for each:

for R1 in ../garrigos/fastq/*_R1.fastq.gz; do
    R2="${R1/_R1/_R2}"
    echo "R1 file: $R1"
    echo "R2 file: $R2"
    echo
done

Search for _R1 and not just R1: in other datasets, the string “R1” may also occur in the sample ID (e.g. ERR1234)!

To run a script for each sample, you would replace the echo lines with a call to a script that accepts both files as arguments. You’ll practice that in the exercise below with a “mock” script, and in a later week, you’ll write such a script for the program TrimGalore.
